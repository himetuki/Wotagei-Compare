# Spec Delta: video-workspace

## ADDED Requirements

### Requirement: 通道持久化 URI 授权按需释放
在 Android 原生平台下，当用户为 CH1 或 CH2 更换新视频或应用插件实例销毁时，系统 MUST 释放此前为该通道申请的持久化 URI 读取权限；若另一通道当前仍引用同一个 URI，则 MUST 保留该共享 URI 的读取权限直到其也被替换或销毁。

#### Scenario: 更换单通道视频后释放旧 URI 授权
- **WHEN** 用户在 CH1 选择视频 A，随后更换选择视频 B（且 CH2 未使用视频 A）
- **THEN** 系统释放视频 A 的持久化 URI 读取权限并仅保留当前活跃通道所需权限，不会随长期反复选片累积系统权限配额

#### Scenario: 双通道选用同一视频时更换一侧不误释放
- **WHEN** 用户在 CH1 和 CH2 均选择视频 A，随后将 CH1 更换为视频 B
- **THEN** 系统保留 CH2 对视频 A 的读取权限，CH2 的预览、音频分析与后续导出仍正常可用

### Requirement: 未消费音频分析载荷覆盖清理
在 Android 原生平台下，当多次连续触发音频分析或通道已切换新视频时，本地代理服务 MUST 覆盖并清理前一次尚未被前端读取的临时音频 PCM 内存载荷，避免未消费的音频数据滞留内存。

#### Scenario: 连续选片覆盖前次未消费的音频载荷
- **WHEN** 用户快速更换同一通道视频或重复触发音频提取，前一次提取的 PCM 数据尚未被前端读取
- **THEN** 系统清理旧音频载荷的索引与内存引用，仅保留最新一次有效提取载荷

### Requirement: Web 端导入 Object URL 释放
在纯 Web 浏览器环境下，当用户在导入步骤为 CH1 或 CH2 更换本地视频文件时，系统 MUST 撤销释放该通道此前生成的旧预览对象 URL（`blob:` URL），防止重复换片导致浏览器堆内存持续增长。

#### Scenario: Web 端重复更换视频释放旧预览链接
- **WHEN** 用户在纯 Web 浏览器调试环境下为 CH1 导入视频 1 后，再次点击 CH1 更换为视频 2
- **THEN** 视频 1 对应的旧 `blob:` 预览 URL 被撤销释放，不再持续占用浏览器对象 URL 引用
