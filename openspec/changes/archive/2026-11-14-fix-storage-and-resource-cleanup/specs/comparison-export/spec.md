# Spec Delta: comparison-export

## ADDED Requirements

### Requirement: 导出临时文件崩溃残留启动清扫
系统在 Android 原生应用启动并初始化媒体导出能力时，MUST 自动扫描应用缓存目录中此前因异常闪退或进程强杀遗留的临时导出文件（`wotagei_export_*.mp4`）并立即删除，严禁仅依赖正常导出流程结束时的清理逻辑。

#### Scenario: 导出途中强杀后重启应用自动清扫残留
- **WHEN** 应用在离线导出生成临时文件期间被系统强杀或发生崩溃，随后用户重新冷启动应用
- **THEN** 应用初始化时自动定位并删除缓存目录中遗留的 `wotagei_export_*.mp4` 文件，应用缓存占用恢复至初始基线

### Requirement: 相册写入失败回滚占位记录
在 Android 10 及以上系统向公共媒体库（`MediaStore`）写入导出 MP4 文件期间，若打开输出流或写入字节流过程中发生异常中断，系统 MUST 立即删除已插入的 `IS_PENDING` 占位记录，严禁在系统相册中遗留未完成或损坏的空占位条目。

#### Scenario: 写入相册中途存储不足或流异常回滚
- **WHEN** 系统在将临时合成 MP4 拷贝至公共媒体库的过程中发生写入异常（如存储空间不足）
- **THEN** 系统立即清理已创建的待定媒体库记录并删除临时合成文件，公共相册及缓存目录均不留存损坏占位文件

### Requirement: Web 端导出 Object URL 释放
在纯 Web 浏览器环境下，当用户在导出工作台再次执行导出生成新下载链接或退出导出工作台时，系统 MUST 释放此前创建的临时下载对象 URL（`blob:` URL），防止导出成片二进制缓冲在页面会话期间持续累积占用内存。

#### Scenario: 连续导出或返回工作台释放旧下载对象
- **WHEN** 用户在纯 Web 浏览器中完成一次导出生成下载链接后，再次发起新导出或返回对比工作台
- **THEN** 先前生成的临时下载 `blob:` URL 被撤销释放，浏览器不再保留上一份导出视频的内存引用
