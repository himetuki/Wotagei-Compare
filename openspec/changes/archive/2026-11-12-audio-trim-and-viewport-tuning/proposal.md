# Proposal

## Why

在 WOTA 艺慢放扒技与动作比对的实际使用中，存在三个直接影响手机端体验的核心问题：
1. **对比台人物主体偏小**：在移动设备窄小横屏上，当前左右分区算法留出过多底部黑边（脚底沉于 85%、主体占 60%），导致动作细节与发力看不清；
2. **三线标定指示框偏位不协调**：在空间标定视图中，横线标签在线内/线上，而垂直中轴与脚部竖线的指示框偏在线身侧边，视觉杂乱且遮挡侧向细节；
3. **长连技视频多曲导致 BPM 测算失真**：WOTA 艺技连视频常包含多首歌、多个连续招式或前后伴奏杂音，全局测算会导致目标招式的 BPM 不准。需要支持在时间标定中直接框取目标招式的起止范围 `[ ]`，使 BPM 仅针对目标招式范围精确测算，且对比台仅对比双方被截取的有效招式交集。

## What Changes

- **对比台人物比例放大与底边沉底**：调整左右分区正交投影算法，将脚底基准线从半区高度的 85% 进一步下沉至约 94%~95%，头顶线微调至约 26%~27%，人体特征高度占比从 60% 显著提升至约 68%~70%，大幅增强手机端动作可见度，同时确保上方挥棒光弧空间完整不被裁切。
- **空间标定指示框全面居中置于线上**：统一三线正交标定（两横一竖、两竖一横）的所有指示框定位策略。将中轴线、左脚线、右脚线的指示框从「侧偏在旁」改造为「水平居中骑在线上」，与头顶、脚底横线标签风格保持一致。
- **对拍步骤升级为时间标定（增加区间截取与局部 BPM 测算）**：
  - 步骤文案与导航条从「CH1 对拍」「CH2 对拍」全面升级为「CH1 时间」「CH2 时间」；
  - 在音频波形轴两端增加可拖动的起止点手柄（类似 `[` 和 `]`），用户可自由截取目标技连招式的起止时间；
  - 每次拖动起止手柄后，系统仅取截取范围内的单声道 PCM 采样数据实时重新运行自相关算法计算局部 BPM；
  - 锚定点（Anchor Time）的绝对数值与绝对位置在拖动起止点时严格保持不变；
  - 对比台统一时间轴计算升级：以两通道各自截取后的有效区间为基准，按锚点对齐后计算两者的有效重叠交集（Intersection Interval），杜绝全片未截取造成的非目标片段对比。

## Capabilities

### Modified Capabilities

- `geometric-alignment`: 调整左右分区人体特征高度占比与沉底比例，统一三线正交标定垂直线指示框居中在线上的视觉定位。
- `timeline-audio-sync`: 升级对拍标定为时间标定，支持音频轴双端 `[` 和 `]` 区间拖拽截取、基于截取范围重新计算局部 BPM，以及对比台基于双通道截取区间的对齐重叠交集计算。
- `video-workspace`: 全局步骤导航栏文案与向导流转契约由「CH1/CH2 对拍」更新为「CH1/CH2 时间」。

## Impact

- **数据结构与契约**：
  - `VideoAudioInfo` 扩展起止截取时间字段（如 `trimRange: { start: number; end: number }`）并暂存解码后的完整 `rawChannelData`（或 AudioBuffer）供局部实时重算 BPM；
  - `calculateUnifiedTimeline` 入参从全时长 `duration` 扩展为接受各视频的有效截取区间；
  - `calculateTriLineSplitScreenPlacement` 调优特征尺度与 Y 轴偏移参数。
- **界面组件**：
  - `App.tsx` 导航标签升级为「CH1 时间」与「CH2 时间」；
  - `GeometryStep.tsx` 垂直线指示框 CSS/定位调整为居中在线上；
  - `AudioStep.tsx` 波形轴增加双端截取手柄 `[` 和 `]`、拖拽交互及局部 BPM 触发重算；
  - `Workbench.tsx` 与 `ExportPage.tsx` 时间轴消费基于截取后区间的交集。
- **依赖与构建**：无新增第三方依赖，纯前端 React + TypeScript + Canvas 算法与 UI 改造。
