# Spec Delta

## MODIFIED Requirements

### Requirement: 统一时间轴映射与双视频速率换算
系统 MUST 根据用户选定的对拍锚点、在时间标定中截取的有效区间 $[trimStart, trimEnd]$ 以及在对比工作台选定的 BPM 对齐策略，计算各自相对速率比 $r_1, r_2$；BPM 对齐策略从 视频2 时间标定步骤中彻底移除；统一时间轴有效范围 MUST 严格采用两路视频在各自截取区间映射后的「交集区间」（Intersection Interval），即基于各自截取起点与终点换算得到的 $start = \max(start_1^{trim}, start_2^{trim})$ 且 $end = \min(end_1^{trim}, end_2^{trim})$，严禁采用未截取的全视频直接求交集，亦严禁截取单边无画面的盲区；播放工作台提供的快捷复位按钮 SHALL 定位并起播至「锚点前 1 秒」（$\tau = -1.0s$，受交集起点与当前 A-B 循环区间截断保护）。

#### Scenario: 启用自选目标 BPM 对齐
- **WHEN** 视频1 为 160 BPM，视频2 为 150 BPM，用户在对比台右下角菜单中选择统一对齐至 160 BPM
- **THEN** 系统计算 视频1 速率比为 1.0、视频2 速率比为 160/150，在两通道各自截取区间映射后的有效交集区间内两者步调完全一致且两端无单边黑屏

#### Scenario: 基于截取区间生成对比交集
- **WHEN** 视频1 在时间标定中截取了 [10s, 30s]（锚点 15s），视频2 截取了 [20s, 45s]（锚点 25s），两者速率比均为 1.0
- **THEN** 统一时间轴上 视频1 的有效区间为 [-5s, +15s]，视频2 的有效区间为 [-5s, +20s]，对比台统一时间轴交集范围严格生效为 [-5s, +15s]，超出 视频1 截取范围的 [+15s, +20s] 不会进入对比台播放

#### Scenario: 快捷跳转至锚点前 1 秒播放
- **WHEN** 用户在播放工作台点击「锚点前 1s」快捷播放按钮
- **THEN** 系统将统一时间轴定位至 $\tau = -1.0s$ 并立即平滑启动双视频同步播放

### Requirement: 七档慢放与逐帧微调播放控制
系统 MUST 支持在播放工作台通过向上弹出的紧凑倍速菜单快速切换 `0.1 / 0.15 / 0.2 / 0.3 / 0.5 / 0.75 / 1.0` 七档播放倍速，并在底栏提供后退/前进单步微调按钮及多粒度步长选择菜单（含固定时间步长、随当前有效 BPM 换算的拍分步长及自定义数值）。

#### Scenario: 切换为 0.1x 超慢放
- **WHEN** 用户在播放工作台点击底栏当前倍速按钮（如 `1.0x`）并从向上展开的菜单中选择 `0.1x`
- **THEN** 两路视频以各自相对速率比乘以 0.1 的速度超平滑同步慢放，菜单自动收起

#### Scenario: 选择节拍或帧步长进行单步微调
- **WHEN** 用户在对比工作台打开步长菜单选择 `1帧(0.033s)` 或 `1/4拍` 后点击后退或前进微调按钮
- **THEN** 双路视频画面按设定步长精准同步跳转至对应统一时间轴时刻并刷新静态对比帧

### Requirement: 时间标定视图锚点帧即时呈现
用户在导入双路视频后进入「视频1」或「视频2」同屏一体化标定视图时，若尚未主动播放或拖动找帧，系统 MUST 在视频元数据就绪后自动将视频定位并渲染至当前对拍锚点时间戳（受有效截取区间 $[trimStart, trimEnd]$ 约束），严禁因组件挂载初期媒体元素尚处于未就绪状态（`readyState = 0`）导致初始寻道被内核静默丢弃、进而使用户看到纯黑等待画面；用户在波形画布上点击或按住水平滑动时 MUST 实时寻道更新视频画面，以便同一视图内精准找出起手姿态与卡拍节拍点。

#### Scenario: 老旧 WebView 初次进入时间标定页即见锚点画面帧
- **WHEN** 用户在运行 Chrome 74 级别 WebView 的 Android 10 设备上进入「视频1」或「视频2」标定视图且尚未手动找帧、也未点击「播放」
- **THEN** 视频元素在元数据就绪后立即同步定位至当前 `anchorTime` 对应时刻并完成画面帧绘制，监看区直接呈现真实视频帧而非纯黑画面

#### Scenario: 同屏波形拖动即时同步视频画面找帧
- **WHEN** 用户在「视频1」底部的音频波形区域按住并拖动至 06.25s 处
- **THEN** 视频画面（含叠加空间三线）实时寻道至 06.25s，用户可直接基于该时刻微调空间三线或点击「设为锚点」

### Requirement: 时间标定与对比台窄横屏底栏无截断及音频上下文复用
时间标定视图的底部控制栏与对比台底部控制栏在 `640×360` 窄横屏叠加 `48px` 三键导航安全区下 MUST 自动收紧内边距或采用紧凑布局，确保时间标定 `BPM` 输入加减区以及对比台 A-B 循环按键、步进微调组、倍速菜单按钮和 `SYNC BPM` 菜单按钮全部完整显示在安全区内；时间标定「试听」功能 MUST 复用单一 `AudioContext` 实例并在用户点击手势中同步唤醒与释放，严禁多次试听触及 Chromium 硬件音频上下文数量上限。

#### Scenario: 640x360 窄屏下时间标定与叠加对比台底栏完整可见
- **WHEN** 用户在 `640×360` 逻辑宽高叠加 `48px` 右侧安全区的横屏视口打开「视频1」时间子视图或切换到叠加模式的「对比台」
- **THEN** 时间标定右侧 `BPM` 加减控件与对比台底栏所有控件（含 A/B 开关、步进微调组、倍速菜单与右下角 `SYNC BPM` 按钮）均完整处于安全区内，不超出视口右边界

#### Scenario: 连续试听锚点十次不触发 AudioContext 配额异常
- **WHEN** 用户在时间标定子视图连续点击「试听」按钮 10 次以上
- **THEN** 系统复用同一个已唤醒的 `AudioContext` 播放卡拍脉冲音，控制台零异常且每次试听正常发声

## ADDED Requirements

### Requirement: 时间标定完成状态小点指示
在「视频1」与「视频2」标定页内，系统 MUST 在用户显式点击「设为锚点」按钮后点亮当前视频顶栏对应的时间标定只读状态小点（该小点不可点击切换），除此之外不弹出任何引导弹窗或阻断提示。

#### Scenario: 点击设为锚点后时间状态小点亮起
- **WHEN** 用户在「视频1」标定视图定位时间游标并点击「设为锚点」
- **THEN** 顶栏「时间」状态指示旁的小点立即切换为点亮状态，未触发任何额外引导提示框

### Requirement: 对比工作台目标时间累加步进微调与冷启防黑屏缓存
对比工作台执行后退或前进步进时 MUST 基于当前目标统一时间轴偏移量即时累加步长并约束在当前有效播放范围（交集区间或已激活的 A-B 循环区间）内，若此前处于播放态则立即暂停，确保高速连点步进按钮不因底层解码延迟而丢失步数；对比台挂载双路 `<video>` 后 MUST 立即对初始时刻（含 `0s`）执行强制解码定格，并在发起寻道前抓拍及非播放态下维护每通道最近已就绪帧离屏缓存（全速播放期间零拷贝直通）：在每次寻道（`seeking` / `readyState < 2`）期间针对有效区间内视频维持上一已就绪帧渲染而不清空为纯黑，消除首次点击步进等待数秒才出图像的黑屏卡顿。

#### Scenario: 播放状态下点击步进并连续快点多下不丢步
- **WHEN** 对比台正在播放且当前时间轴位于 `+1.00s`，步长设为 `0.05s`，用户快速连续点击前进微调按钮 4 次
- **THEN** 播放立即停止，目标统一时间轴连续累加 4 个步长跳转至 `+1.20s` 附近并完成对应双画面帧渲染，不出现仅前进 1 步的丢步现象

#### Scenario: 首次点击步进无纯黑清屏等待
- **WHEN** 用户载入长 GOP 高清视频进入对比台暂停状态后，首次点击前进或后退步进按钮
- **THEN** 寻道过渡期间画布持续保留有效参考画面而不闪黑，目标解码帧到达后立即刷新显示，无 2~3 秒纯黑失画现象

### Requirement: 高精度多拍谐波梳状 BPM 检测
音频 BPM 检测引擎 MUST 采用高时间分辨率（约 ~250 Hz 帧移 ~4ms 配合 ~10ms 重叠 RMS 窗）提取去均值正差分起音包络，并利用覆盖 $1T, 2T, 4T, 8T, 16T$ 多拍整数倍周期的谐波梳状自相关加权先验与分级连续寻优算法测定曲速（含 `detectBpmFromSlice` 截取区间重算），在不同采样率（`44.1kHz / 48kHz / 16kHz`）下避免粗步长栅格量化与单拍微扰漂移（例如确保 `[A]ddiction` 准确测为 `164` 而非 `163`、实拍《嘘の火花》片段准确测为 `188` 而非 `190`）。

#### Scenario: 44.1kHz 与 48kHz 真实曲目 BPM 精准稳定测算
- **WHEN** 用户导入 `[A]ddiction.mp4`（44.1kHz）或《嘘の火花》片段（48kHz / 188 BPM）并在波形上截取对应段落重算 BPM
- **THEN** 检测算法稳定输出四舍五入整数 BPM 为 `164` 与 `188`，不因采样率差异或单拍切分瞬态而偏离为 `163` 或 `190`
