# Spec Delta

## ADDED Requirements

### Requirement: 导出工作台共享双路视频源即时首帧与窄屏操作区完整可见
导出工作台 MUST 直接复用对比工作台所持有的两路 `<video>` 解码源并由引擎接管控制，严禁再创建额外 2 路 `<video>` 造成 4 路并发解码器占坑；进入「导出片段」后，系统 MUST 立即绘制并呈现有效预览帧，不在未全就绪前锁死半黑残帧；在逻辑高度 `360px` 的 16:9 横屏设备上，右侧导出面板的「开始渲染导出」按钮 MUST 始终完整展示在首屏视口内，严禁向下溢出截断。

#### Scenario: 进入导出页并发视频节点仅 2 个且即时呈现画面
- **WHEN** 用户在 Chrome 74 级别 Android 10 设备上从对比工作台切换至「导出片段」
- **THEN** 文档中活跃的 `<video>` 元素总数为 2 个而非 4 个，导出预览画布迅速呈现清晰的左右或叠加对比首帧而非持续 1 秒全黑

#### Scenario: 640x360 横屏导出页右侧主按钮首屏完整可见
- **WHEN** 用户在 `640×360` 逻辑视口进入「导出片段」页面
- **THEN** 右侧面板的「开始渲染导出」按钮底边界位于视口高度 `360px` 之内，无需滚动即可直接点击

### Requirement: 老旧 WebView 无 WebCodecs 时兼容录制导出降级
当运行环境不支持 WebCodecs（`VideoEncoder` 不可用，如 Chrome 70~93 老版本手机）时，系统 MUST 自动切换为基于实时画布流与音频混流的兼容录制导出模式，按当前设定倍速回放 A-B 区间并录制成标准 WebM 视频（携带当前所选节拍器或单侧原声音轨），支持进度百分比更新、取消中断与下载或原生保存，并在提示条明确告知处于兼容录制模式。

#### Scenario: Chrome 74 老版本手机完整跑通导出流程
- **WHEN** 用户在无 `VideoEncoder` 的 Android 10（Chrome 74 WebView）上进入「导出片段」并点击「开始渲染导出」
- **THEN** 系统自动采用兼容录制导出管线，进度从 `0%` 推进至 `100%`，最终成功生成非空可下载的 `.webm` 视频文件，全程零报错异常
