# Design: 闭环截取区间局部自相关与速度先验谐波校准

## Context

在多歌曲拼接的技连视频中，时间标定步骤负责测定目标招式的局部 BPM。目前底层能量自相关算法由于固定截取前 45 秒，导致停止手柄大范围调整时计算输入无变动；且自相关对 3+3+2 附点切分音敏感，将 165 BPM 错判为 110 BPM。详见 [proposal.md - Why](./proposal.md#why)。

## Goals / Non-Goals

**Goals:**
- **完全闭环数据源**：`detectBpmFromSlice` 传入的 PCM 子切片长度就是自相关搜索的数据上限，删除 45 秒固定截断，实现停止手柄拖动实时联动。
- **消灭 110 与 165 串扰**：引入以 168 BPM 为中心的对数正态先验概率分布权重，配合 1.5x / 2x 谐波复核，压制切分音亚谐波假峰。
- **丝滑交互与防抖计算**：手柄拖拽过程中仅同步更新视频游标与选区遮罩，重算逻辑在手柄释放（`PointerUp`）或防抖后触发，避免中间半成品过渡态污染 BPM。

**Non-Goals:**
- 不引入重型 WebAssembly 音频分析库（如 Essentia.js），坚持轻量级纯 TypeScript 纯数学实现。
- 不更改播放工作台（Workbench）和导出（Export）的双视频同步锁相环逻辑，仅改进单通道局部 BPM 的检测准确性。

## Decisions

### 1. 彻底废除 45 秒硬编码截断，实施纯切片闭环
- **决定**：在 `detectBpmFromPcm` 中删除 `Math.min(onsets.length, Math.floor(45 * envelopeSampleRate))`，直接采用传入切片的全部可用起音数据 `onsets.length` 进行自相关。
- **架构决策记录**：参见 [AgDR-0020 闭环区间自相关与WOTA艺速度先验谐波校准](../../../docs/decisions/AgDR-0020-闭环区间自相关与WOTA艺速度先验谐波校准.md)。
- **备选方案**：保留固定窗口但根据选区中心滑动采样。被否决，因为招式长短不一（5s 到 60s），全量闭环计算量（<50ms）在纯 JS 遍历中完全可承受，不需要人为制造盲区。

### 2. 对数正态先验加权（Log-Normal Tempo Prior）
- **决定**：自相关得分计算引入先验衰减乘子：
  $$W(bpm) = \exp\left( -\frac{(\log_2(bpm) - \log_2(168))^2}{2 \cdot 0.35^2} \right)$$
  对各 Lag 对应的自相关系数进行加权加乘。
- **依据**：WOTA 艺常用歌曲（如地下偶像、ACG 神曲）90% 以上速度分布在 150 ~ 190 BPM。当 110 BPM 与 165 BPM 发生冲突时，先验加权能直接将 110 的置信度衰减至 0.5 以下，确保 165 峰值胜出。

### 3. 1.5 倍频（3:2）与 2 倍频谐波共振校验
- **决定**：若加权后最强候选仍落在 $[95, 125]$ 区间，主动探测其 $1.5\times$（如 $110 \times 1.5 = 165$）以及 $2\times$ 滞后周期处的局部峰值。若 1.5x 峰值强度超过该候选峰的 35%，判定为切分音造成的亚谐波假象，强制升级为 1.5 倍真实节拍。

### 4. 手柄拖动防抖与释放更新策略
- **决定**：在 `AudioStep.tsx` 中，`handlePointerMove` 仅负责 `setTrimStart`/`setTrimEnd` 和 `video.currentTime` 寻帧；在 `handlePointerUp` 时执行一次确定性 `recalculateBpmForTrim`，并在拖拽过程中附加 250ms 防抖计时器作为辅助保底。

## Risks / Trade-offs

- [极短音频切片（< 2秒）周期不充分] → 在 `detectBpmFromSlice` 中设置 2.0 秒底线守卫：若切片短于 2 秒，直接保留用户前序设定的 BPM，不进行自相关猜测，避免短信号边界失真。
- [极长视频全量导入时的性能消耗] → 仅在导入全视频初次检测时保持最大 60 秒上限（避免几十分钟大视频卡死解码），而在标定截取切片时由于已被用户裁剪，严格采用闭环区间。
