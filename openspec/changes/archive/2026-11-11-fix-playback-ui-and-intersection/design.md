# Design: 移动端同台对比交集时间轴与沉浸监看交互重构

## Context

在经过多轮移动端实机验证后，当前界面暴露了影响核心对比体验的若干痛点（详见 [proposal.md](./proposal.md) 的“Why”部分）：
1. 顶栏存在装饰性字符 `WC-MON` 以及右侧截断露出的多余黄色按钮，非对比台无需也不应出现黄色操作项；
2. 空间标定页面三线标注文字在靠近画幅底部时与进度条重叠遮挡，且携带无用百分比数据；
3. 音频对拍控制栏塞入过多微调层级（1F 与 20ms），挤占了右侧核心单一真实源 BPM 微调按键；
4. 左右半区模式下人物画面过小，对比模式默认半透明叠加不符合初次直觉，翻转图标误用了上下对顶形状；
5. 统一时间轴采用并集区间导致前后两端出现大段无意义的单边黑屏，且缺乏起手动作观察的提前 1 秒预卷播放机制；
6. 导出台右侧子容器高度溢出，核心“开始渲染导出”按钮无法显示在移动端横屏第一视口中，且左侧画布无法进行动态连续预览。

## Goals / Non-Goals

**Goals:**
- **清除所有顶栏视觉残留**：移除 `WC-MON`，移除向导中的多余黄色按钮；顶栏全流程提供可随时点击弹出修改的 CH1/CH2 BPM 徽章。
- **空间标定防遮挡布局**：头顶黄线标注框改至左下方，脚底绿线标注框改至右上方；去除百分比；精简模型切换文案；移除 `< 1F` 与 `1F >`。
- **音频对拍空间释放与直接输入**：移除 1F 与 20ms 按钮；锚点位置直接作为数字输入框，支持点击手动输入精准秒数；确保右侧 BPM 的 `+`、`-` 与数值输入 100% 舒展呈现。
- **左右分区默认与画面放大**：默认模式变更为左右分区；修改镜像翻转图标为正确的水平镜像矢量图标；将左右分区人物特征投影比例提升至 60%，收窄四周黑边。
- **统一时间轴交集重构 (Intersection)**：统一时间轴主有效区间计算方式由 $\text{Union}(span_1, span_2)$ 彻底变更为 $\text{Intersection}(span_1, span_2)$，播放与导出区间严格限制在此交集内；提供「锚点前 1s 播放」快捷起播。
- **导出台功能补齐与横屏零溢出**：增加预览画布的播放/暂停控制；导出台 A-B 区间全面适配交集；重构右侧面板纵向弹性排版（缩减内边距与字体，设置合理的弹性盒伸缩），确保在 360px~450px 横屏视口下“开始渲染导出”按钮完整可见且不下溢。

**Non-Goals:**
- 不引入外部庞大 UI 组件库或复杂模态框，全部采用原生轻量 React + 纯 CSS 解决。
- 不做多段副歌非线性拼接触发，保持单锚点对齐的核心模型。

## Decisions

架构决策记录详见：[AgDR-0009 移动端同台对比交集时间轴与沉浸监看交互重构](../../../docs/decisions/AgDR-0009-移动端同台对比交集时间轴与沉浸监看交互重构.md)。

### 决策 1：统一时间轴全面切为交集计算 (Intersection Interval)

- **实现方案**：
  在 `src/core/timeline.ts` 中，`calculateUnifiedTimeline` 算法：
  ```ts
  const intersectStart = Math.max(start1, start2);
  const intersectEnd = Math.min(end1, end2);
  ```
  在返回对象中，以 `intersectInterval: { start: intersectStart, end: Math.max(intersectStart + 0.1, intersectEnd) }` 替换原先主导的 `unionInterval`。所有播放滑块、导出范围以及判断合法性的上下限均以 `intersectInterval` 为基准。两端若存在某一视频超出交集的时间段，直接在计算时被截断排除，确保同台对比画面的每 1 帧双方均有有效动作。

### 决策 2：左右分区三线投影参数重平衡

- **实现方案**：
  在 `src/core/geometry.ts` 中的 `calculateTriLineSplitScreenPlacement`：
  将 `targetFeatureH` 从 `halfViewport.height * 0.42` 调整为 `halfViewport.height * 0.60`。
  人物整体面积提升约 1.43 倍，左右两侧与下方的无用黑边大幅度削减，同时人物头顶依然保留约 25%~30% 的上方纵深，足够容纳荧光棒大光弧，兼顾画面冲击力与动作完整度。

### 决策 3：空间标定标注角标反向错位防遮挡

- **实现方案**：
  在 `src/components/GeometryStep.tsx` 中：
  - 头顶横线（yA）：角标定位由 `left: 10px, bottom: 24px` 变为 `left: 10px, top: 12px`（黄线左侧下方）；
  - 脚底横线（yB）：角标定位由 `left: 10px, top: 24px` 变为 `right: 10px, bottom: 12px`（绿线右侧上方）；
  - 即使脚底线贴合画幅最底部（yB ≈ 1.0），角标也在绿线之上，完全不受底部找帧栏和进度条的重叠遮挡；
  - 标签移除 `(val * 100).toFixed(1)%`，仅展示纯文字「头顶」「脚底」「中轴」；
  - 移除 `< 1F` 与 `1F >`，底部保留播放/暂停与时间进度。

### 决策 4：音频对拍与顶栏 BPM 全局随时可改

- **实现方案**：
  1. `App.tsx` 顶栏：
     - 移除 `WC-MON` 文本；
     - 移除右侧在非对比台时的黄色下一步按钮；
     - 渲染 `CH1 ... BPM` 和 `CH2 ... BPM` 徽章，点击时直接进入编辑态（原生 input 或内联微型输入框），允许用户直接输入新数值，回车或失焦即刻调用 `handleAudio1Change` / `handleAudio2Change` 更新全局视频状态。
  2. `src/components/AudioStep.tsx`：
     - 移除 `< 1F`、`1F >`、`-20ms`、`+20ms`；
     - 将原只读文本 `锚点 8.134s` 重构成支持直接点击修改的数字输入组件 `<input type="number" step="0.001" />`，支持精确到毫秒级键入；
     - 释放横向空间后，右侧 TAP 测速、BPM `-`、数字输入与 `+` 按钮自然舒展排列，彻底根治截断问题。

### 决策 5：工作台默认模式、镜像图标与起播点重构

- **实现方案**：
  在 `src/components/Workbench.tsx` 中：
  - `initialMode` 默认值在 `App.tsx` 中置为 `'split-screen'`；
  - 镜像图标：用纯正左右翻转矢量图标（例如水平双向箭头或水平镜像对称三角形）替换原 `FlipHorizontal2`（该图标在某些渲染下表现为垂直上下关系）；
  - 快捷播放：将原 `锚点 0.00s` 替换为 `锚点前 1s`，点击后执行 `seekToTau(Math.max(timeline.intersectInterval.start, -1.0))` 并自动触发播放；
  - 移除底部控制栏的 `< 1F` 和 `1F >`。

### 决策 6：导出台横屏弹性排版与动态预览

- **实现方案**：
  在 `src/components/ExportPage.tsx` 中：
  - 左栏：在预览画布下方增加 `播放 / 暂停` 预览按钮，使用 `requestAnimationFrame` 驱动 `previewTau` 在 `[clipStart, clipEnd]` 内循环或单次按慢放倍速步进渲染；
  - 右栏：重构 `.panel-box` 内部的间距、padding 与字体大小，使用 `flex: 1; min-height: 0; overflow-y: auto;` 或纯紧凑网格（grid/flex），将“起止截取”、“成片统计”与底部“开始渲染导出”按钮紧凑包裹，确保整体在移动端 360px 高度下零溢出，按钮始终牢牢固定在可视区域内。

## Risks / Trade-offs

- **[Risk]** 取两视频交集后，如果两个视频的动作起手点锚点标定相差过大，可能会导致交集时长过短。
  → **Mitigation**: 界面在计算出交集后，若交集时长不足 2 秒，在时间轴旁给予友好黄色提示（“有效交集过短，请检查对拍锚点”），帮助用户重新校对起拍位置。
- **[Risk]** 左右半区人物放大至 60% 后，某些超大幅度跳跃或极高挥棒动作可能轻微触碰画面顶边。
  → **Mitigation**: 顶部保留约 25%~30% 的天空留白，且底层依然保留半透明全景视频画幅（Cover 背景），即使偶有出圈也不会出现生硬裁切感。
