# Spec Delta

## MODIFIED Requirements

### Requirement: 双路本地视频文件导入与状态持久驻留
系统 MUST 支持用户在导入步骤中分别选择并载入两个本地视频文件并展示分辨率、时长与检测 BPM，导入页不设初始对比模式切换或演示样本生成按钮；双通道槽位统一标记为「CH1」与「CH2」，严禁使用「基准源」「对比源」等定性称谓；用户选取文件后，系统 MUST 立即将槽位更新为已就绪并展示文件信息，严禁在等待媒体元数据期间保持无响应的「未载入」；在面对老旧 WebView 内核、大尺寸视频或元数据探测异常时，系统 MUST 提供超时（≤ 2.5s）保底与安全降级策略，确保任意有效 MP4 视频均能顺利导入并允许进入后续步骤；系统中的底层视频支撑节点 MUST 保持在浏览器渲染管线中活跃（严禁使用 `display: none` 导致 GPU 纹理断流），且全界面 CSS 边距在老旧内核下 MUST 具备固定数值回退保障；只要用户不主动更换视频，其几何与音频参数 SHALL 永久保留在内存中，在任意步骤间跳转时严禁丢失已导入的视频。

#### Scenario: 首页切换模式保留视频
- **WHEN** 用户导入两个视频并进入后续标定或对比工作台后，再次切回导入步骤查看
- **THEN** 系统完整保留两个视频的引用、几何标定与音频参数，不发生视频丢失或重置，且槽位仅标识为 CH1 与 CH2，无基准源/对比源文案

#### Scenario: 用户选取视频后获得即时视觉响应
- **WHEN** 用户通过文件选择器选取本地 MP4 视频并返回应用
- **THEN** 对应通道槽位立即呈现文件名与文件大小，状态即刻由「未载入」转变为「信号已就绪」或「参数解析中」，主操作按钮在双通道均选定后即可解锁

#### Scenario: 老旧内核或元数据解析异常触发超时保底
- **WHEN** 运行在老旧 WebView 内核上的设备因媒体元素限制未触发或延迟触发 `loadedmetadata` 事件
- **THEN** 系统在 2.5 秒内自动采用标准分辨率（1920×1080）与保底时长，顺利完成视频注册并消除阻塞，允许用户正常推进向导

#### Scenario: 大尺寸视频文件导入触发内存防崩保护
- **WHEN** 用户导入文件体积超过 80MB 的高码率高清视频文件
- **THEN** 系统跳过全量 PCM 解码以保护 WebView 堆内存，采用安全预设 BPM（160 BPM）与快速音轨占位，杜绝进程 OOM 崩溃闪退

#### Scenario: 老旧内核 Canvas 视频纹理持续刷新
- **WHEN** 用户在运行老旧 Chromium 内核的设备上进入对比工作台或导出预览
- **THEN** 底层视频支撑节点在保持视觉隐蔽的同时维持活跃渲染树挂载，Canvas 能持续正确获取最新解码视频帧，不出现画面黑屏或首帧冻结
