# Proposal

## Why

在 Wotagei-Compare 应用中，当用户从「对比台」切换至「导出片段」并返回对比台时，对比台主画布会出现视频不可见（黑屏、画面丢失或无法播放）的严重缺陷，只有切换至前面步骤（如空间标定或时间标定）再切回对比台才能临时恢复。

其根因在于：
1. `Workbench` 内部通过早期条件返回渲染 `<ExportPage>`，导致对比台底层的 `<video>` 解码源 DOM 节点与 Canvas 视口被强制卸载；当切换回对比台时，挂载了全新 `<video>` DOM 元素，但与视频相关的同步驱动引擎（`DualVideoSyncEngine`）却在无依赖的 `useEffect` 中保留了早已销毁的幽灵视频句柄，未能重新连接新节点；
2. 新挂载的视频节点在元数据未就绪（`readyState < 2`）时，Canvas 渲染循环可能因绘制未就绪视频抛出异常中断 RAF 渲染，且 `SafeVideoController` 在元数据未就绪时将寻道目标误截断为 0 并静默丢弃；
3. 切换至前面步骤时，`App.tsx` 彻底卸载了 `Workbench` 组件，因此切回时执行了全新挂载生命周期，从而误打误撞“恢复”了视频。

为了保障用户在对比监看、片段微调与截取导出之间流畅无阻的反复切换体验，必须在架构与状态流转层面彻底修复该视频不可见问题。

## What Changes

- **对比台与导出页 DOM 容器常驻与非破坏性切换**：在 `Workbench` 中废除导致底层视图被整体卸载的早期条件返回分支，将对比台主画布视图与 `<video>` 解码元素常驻保持在 DOM 树中；当进入导出模式时，将对比台视口置为隐藏并自动挂起播放驱动，同时挂载导出视图；返回对比台时即时恢复展示，避免视频 DOM 重复销毁与重新初始化开销。
- **视频节点动态自愈与生命周期感知**：在 `Workbench` 中建立针对底层 HTMLVideoElement 引用的生命周期自愈机制；即便发生 DOM 节点重载或外部刷新，同步引擎自动重新接管新节点并触发对齐寻道同步（`seekToTau`），确保解码状态始终与时间轴游标一致。
- **渲染循环硬件就绪屏障与容灾守护**：在 Canvas 2D 渲染管线与 `Workbench` 渲染循环中加入视频就绪状态检查（`readyState >= 2` 与安全尺寸判定）；将渲染执行包裹于异常捕获防线中，杜绝任何底层浏览器绘制异常中断 `requestAnimationFrame` 主渲染时钟。
- **安全寻道器元数据加载拦截**：优化 `SafeVideoController.seek`，在视频元素 `readyState < 1`（元数据尚在加载、时长为 `NaN`）时挂起寻道并监听 `loadedmetadata` / `loadeddata` 事件，严禁将时间戳错误截断为 0 并提前声明成功，彻底消除有效时间戳丢失导致的黑屏与画面停滞。
- **架构决策记录**：根据项目规范，新增架构决策记录 `docs/decisions/AgDR-0019-对比台DOM持久化与视频挂载自愈状态机.md`。

## Capabilities

### New Capabilities

（无新能力新增）

### Modified Capabilities

- `video-workspace`: 增强对比播放工作台的步骤切换与多视图互斥渲染契约，保证在「对比台」与「导出片段」或外部各步骤反复切换时，双通道视频解码源保持持久可用或即时自愈恢复，严禁出现视频黑屏、画面不可见或同步时钟失效。

## Impact

- **受影响代码**：
  - `src/components/Workbench.tsx`: 消除早期条件返回，改为双视图并存/显隐切换，添加视频 ref 变动感知与切回自愈寻道。
  - `src/core/sync-engine.ts`: 完善 `SafeVideoController` 元数据加载拦截守卫与 `attachVideos` 重新关联机制。
  - `src/core/renderer.ts`: 增强视频渲染就绪守卫与尺寸保护。
  - `docs/decisions/AgDR-0019-对比台DOM持久化与视频挂载自愈状态机.md`: 新增架构决策记录。
- **性能与资源**：在横屏移动端 WebView 中，切换至导出片段时对比台视频元素挂起解码与时钟驱动，避免占用多余硬件解码实例与 CPU/GPU 算力；切回对比台时获得零延迟画面重现。
