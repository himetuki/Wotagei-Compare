# video-workspace Specification

## Purpose

提供 Wotagei-Compare 应用基础工作区底座，负责跨平台原生环境下的强制横屏锁定、双路视频导入与状态持久化、全屏线性三线对齐向导流转、播放工作台主布局以及单项快速微调通道。

## Requirements


### Requirement: 全程强制横屏锁定与界面适配
系统在移动端原生与浏览器环境下运行时，MUST 强制锁定为横屏（Landscape）方向，所有向导步骤与播放页面 SHALL 针对横屏视口进行无黑边拉伸的自适应布局。

#### Scenario: 移动设备启动或旋转屏幕
- **WHEN** 用户在移动设备上启动应用或物理旋转设备至竖屏方向
- **THEN** 系统保持横屏显示方向锁定，界面元素按横屏宽高比自适应排布

### Requirement: 双路本地视频文件导入与状态持久驻留
系统 MUST 支持用户在导入步骤中分别选择并载入两个本地视频文件并展示分辨率、时长与检测 BPM，导入页不设初始对比模式切换或演示样本生成按钮；双通道槽位统一标记为「视频1」与「视频2」，严禁使用「基准源」「对比源」等定性称谓；用户选取文件后，系统 MUST 立即将槽位更新为已就绪并展示文件信息，严禁在等待媒体元数据期间保持无响应的「未载入」，且当用户在异步音频或元数据解码完成前提前点击推进至标定页时，解析完成的结果 MUST 按视频 URL 安全合入主状态并在标定页无感同步（同时不覆盖用户已手动编辑的标定参数）；在 Android 原生平台下，系统 MUST 通过系统原生视频文件选择器获取持久化 `content://` URI 及支持随机寻道的本地流式预览 URL，并通过原生流式音频解码提取单声道 PCM 数据进行波形与 BPM 测算，彻底消除超过 80MB 大视频被跳过音频解析的截断限制，严禁通过 WebView 沙盒全量读取大文件内存；在纯 Web 浏览器环境下保持 `<input type="file">` 与安全降采样探测逻辑（含 ≤ 2.5s 元数据超时保底与移动端 WebView >80MB / 桌面端 >512MB 内存保护）；系统中的底层视频支撑节点 MUST 保持在浏览器渲染管线中活跃（严禁使用 `display: none` 导致 GPU 纹理断流），且全界面 CSS 边距在老旧内核下 MUST 具备固定数值回退保障；只要用户不主动更换视频，其几何与音频参数 SHALL 永久保留在内存中，在任意步骤间跳转时严禁丢失已导入的视频。

#### Scenario: 首页切换模式保留视频
- **WHEN** 用户导入两个视频并进入后续标定或对比工作台后，再次切回导入步骤查看
- **THEN** 系统完整保留两个视频的引用、几何标定与音频参数，不发生视频丢失或重置，且槽位仅标识为 视频1 与 视频2，无基准源/对比源文案

#### Scenario: 用户选取视频后获得即时视觉响应
- **WHEN** 用户在 Android 原生应用中通过系统原生视频选择器选取本地 MP4 视频并返回应用
- **THEN** 应用获得持久化 `content://` URI 与本地流式预览 URL，对应通道槽位立即呈现文件名与视频参数，主操作按钮在双通道均选定后即可解锁

#### Scenario: 老旧内核或元数据解析异常触发超时保底
- **WHEN** 运行在 Web 浏览器或老旧 WebView 内核上的设备因媒体元素限制未触发或延迟触发 `loadedmetadata` 事件
- **THEN** 系统在 2.5 秒内自动采用标准分辨率（1920×1080）与保底时长，顺利完成视频注册并消除阻塞，允许用户正常推进向导

#### Scenario: 大尺寸视频文件导入触发内存防崩保护
- **WHEN** 用户在纯 Web 浏览器调试环境下导入超过安全内存阈值（移动端 WebView >80MB、桌面端 >512MB）的高码率高清视频文件
- **THEN** 系统跳过全量 PCM 解码以保护 WebView 堆内存，采用安全预设 BPM（160 BPM）与快速音轨占位，杜绝进程 OOM 崩溃闪退

#### Scenario: 解码未完成提前推进标定页时异步无感补齐
- **WHEN** 用户导入较长高清视频后尚未等「解析中」完成即点击「开始标定」进入「视频1」
- **THEN** 后台音轨解析完成后真实波形与测算 BPM 自动合入主状态并即时刷新标定页（同时保留用户已拖拽调整过的三线、锚点或手动 BPM）

#### Scenario: Android 原生平台导入超过 80MB 大视频完整解析波形与音轨
- **WHEN** 用户在 Android 原生应用中选取文件体积大于 80MB 的高清本地视频文件
- **THEN** 系统通过原生流式解码提取音频 PCM 并完成真实波形与 BPM 测算，不发生 WebView 堆内存溢出闪退，且后续导出单侧原声时具备完整有效音频

#### Scenario: 老旧内核 Canvas 视频纹理持续刷新
- **WHEN** 用户在运行老旧 Chromium 内核的设备上进入对比工作台或导出预览
- **THEN** 底层视频支撑节点在保持视觉隐蔽的同时维持活跃渲染树挂载，Canvas 能持续正确获取最新解码视频帧，不出现画面黑屏或首帧冻结

### Requirement: 线性全屏向导状态流转
系统 MUST 支持按「导入 → 视频1（空间定线与时间对拍） → 视频2（空间定线与时间对拍） → 对比台 → 导出片段」的 5 步顺序推进全屏标定与对比导出，过程中单视频 SHALL 占满横屏主视口以保证最高标定精度，并在标定视图内提供显式的「下一步」按钮顺畅流转至下一向导步骤。

#### Scenario: 依序完成向导进入播放工作台
- **WHEN** 用户完成双路视频导入，依次在「视频1」与「视频2」步骤内完成三线空间定线与时间对拍锚点设定，并点击「下一步」
- **THEN** 系统按顺序流转并进入同台对比播放工作台并加载双方对齐参数

### Requirement: 模式无缝切换与单项快速微调
系统 MUST 在顶部导航栏提供统一的全局步骤分段直达条，彻底移除所有数字标号（`01`~`06`），采用 5 个精炼直观标签（`导入` / `视频1` / `视频2` / `对比台` / `导出片段`），确保在移动端横屏狭窄视口下严禁挤占导航空间；当双视频载入后允许用户在任意环节一键直达目标步骤微调参数，对比工作台初始对比模式与初始三线模型 MUST 读取应用默认偏好配置（出厂默认左右分区与两横一竖），并支持在工作台无缝切换左右分区与半透明叠加模式。

#### Scenario: 快速微调单项参数
- **WHEN** 用户在对比工作台点击顶部步骤条中的「视频2」
- **THEN** 系统直接展示视频2 同屏的既有空间三线与时间波形参数及截取区间，修改后点击顶部「对比台」或「下一步」即刻返回工作台

#### Scenario: 初始进入工作台默认左右分区
- **WHEN** 用户未更改默认对比模式设置、完成标定并首次进入对比播放工作台
- **THEN** 系统默认以左右分区模式呈现双视频对比画面

#### Scenario: 初始进入工作台遵循默认对比模式偏好
- **WHEN** 用户在设置页将默认对比模式设为「半透明叠加」，完成标定首次进入对比播放工作台
- **THEN** 系统按照设置页中配置的默认对比模式呈现半透明叠加双视频对比画面

### Requirement: 对比播放工作台交互与重新标定
播放工作台 MUST 提供沉浸式横屏视口，顶部集成全局步骤分段直达条以及可折叠的对比模式、声音源与独立镜像工具栏，底部集成统一时间轴、A-B 循环设点与清除、锚点复位、播放/暂停、多粒度步进微调、可弹出式七档慢放菜单、叠加透明度滑块与 BPM 对齐策略菜单；在工作台与「导出片段」或其他向导步骤相互切换时，系统 MUST 保持底层视频解码节点及播放时钟的可用性与自愈性，严禁出现视频黑屏、画面不可见或控制器与新节点脱节卡死。

#### Scenario: 用户请求重新标定
- **WHEN** 用户在播放工作台点击顶部步骤条的「视频1」
- **THEN** 系统保留当前已载入的双视频引用，并直接切换至视频1 标定视图

#### Scenario: 对比台与导出片段反复切换画面持久展示
- **WHEN** 用户在对比工作台点击顶部「导出片段」进入导出视图后，点击返回按钮或点击顶部导航栏中的「对比台」切回对比工作台
- **THEN** 对比工作台主画布立即呈现对应的双通道视频画面，视频解码节点与 Canvas 渲染保持可用，不出现黑屏、画面不可见或播放/暂停控制失效

#### Scenario: 切换至前期步骤再返回对比台画面正确展示
- **WHEN** 用户从对比工作台切换至「视频1」或「视频2」微调后，再次点击「对比台」或「下一步」
- **THEN** 对比工作台自动重新完成视频节点与同步引擎的绑定与初相定位，主画布完整呈现当前时间戳的双通道对比画面，播放与步进微调功能正常可用

### Requirement: 专业影视监视器极简暗黑视觉规范
系统全界面 MUST 采用纯黑与深炭灰底色、严格统一的语义强调色（全站 `A` 标记与端点为蓝色、`B` 标记与端点为绿色）、全矢量几何图标与等宽数字时间码，严禁在任何视图中渲染 Emoji 字符或无交互装饰性文字（如 WC-MON）；顶栏「导入」左侧放置软件图标按钮并以灰色竖线与后续步骤区隔开，右侧 BPM 徽章仅在「对比台」显示，单视频标定步骤右侧显示只读「空间● / 时间●」、模型下拉、镜像与「下一步」，全软件通道称谓统一为「视频1」「视频2」。

#### Scenario: 界面纯净度与图标检查
- **WHEN** 用户浏览导入页、单视频标定页、对比工作台及导出页
- **THEN** 顶栏最左侧呈现软件图标按钮及右侧灰色竖线隔断，左侧不显示 WC-MON，顶栏右侧在非对比台步骤不显示 BPM 徽章（对比台常驻显示且支持点击修改），全界面用户可见通道标识严格为 视频1 与 视频2（无 CH1/CH2 文案）

#### Scenario: 狭窄横屏视口零截断检查
- **WHEN** 用户在可用逻辑宽度仅 640px~850px 的横屏设备（含侧边金刚键）上浏览各视图
- **THEN** 顶栏左侧软件图标与灰色竖线、5 步顶栏步骤按钮、顶栏右侧控件以及各视图底部操作面板均完整展示，不被挤出屏幕边缘，不发生截断

#### Scenario: 全流程任意位置点击顶栏修改 BPM
- **WHEN** 用户在对比工作台中点击顶栏右上角的「视频1 188 BPM」徽章
- **THEN** 系统激活手动数值输入，用户输入新数值并确认后，系统立即更新对应视频的基准 BPM 并同步重算所有关联时间轴与节拍刻度（在非对比台步骤中顶栏不显示该徽章）

### Requirement: 系统状态栏与虚拟金刚键安全区避让
系统 MUST 在横屏运行时主动避让操作系统的常驻状态栏（Status Bar）、虚拟按键导航栏（经典金刚键，Navigation Bar）及屏幕物理缺口（Display Cutout）；原生工程 MUST 将窗口背景配置为纯黑并开启打孔屏短边全屏延伸（`shortEdges`），严禁在打孔避让时露出浅色系统底色；应用底色全屏铺满的同时，全部导航步骤选项卡、操作按钮、时间轴控件、状态指示徽章及有效交互区域 SHALL 通过 CSS 安全区变量约束在设备物理安全区域内，严禁与系统级按键或状态栏发生物理遮挡与点击误触。

#### Scenario: 包含常驻状态栏的横屏设备渲染
- **WHEN** 用户在开启常驻状态栏的移动设备上横屏运行应用
- **THEN** 系统顶部全局导航栏自动向下收缩状态栏对应的高度边距，导航栏内的文字、步骤标签与操作按钮完全显示在状态栏下方，不产生文字与图标重叠

#### Scenario: 包含经典金刚键（三键导航）的设备横屏运行
- **WHEN** 用户在右侧常驻金刚键导航栏的 Android 设备上横屏运行应用
- **THEN** 系统所有视图的右侧边界自动向内缩进金刚键对应宽度，全局导航栏最右侧的「下一步」按钮、BPM 徽章及工作台右侧控件均显示在金刚键左侧安全区，点击「下一步」时不触发系统返回或桌面导航键

#### Scenario: 底部控制栏避让底部虚拟按键或手势条
- **WHEN** 用户处于空间标定、音频对拍或对比工作台等包含底部控制栏的视图
- **THEN** 底部控制栏内容区域自动向上增加安全边距，播放按钮、步进微调按钮及时间轴进度条完全脱离底部系统手势指示条与虚拟按键冲突区域

#### Scenario: 打孔/刘海全面屏横屏运行零白边
- **WHEN** 用户在带有前置摄像头打孔或刘海缺口的 Android 设备上横屏运行应用
- **THEN** 应用主窗口向屏幕两侧短边无缝延展铺满，不产生任何原生浅色避让白边，缺口侧的内容依据 `env(safe-area-inset-left)` 保持合理内边距

### Requirement: 移动端运行时语法兼容与首屏致命异常自诊断展示
构建打包产物 MUST 兼容现代主流及稍旧内核（Chrome 70+）的 Android System WebView，不仅在构建层支持 ES2018 语法标准，应用源码在标准库调用上 MUST 严格遵守 ES2018 运行时边界（严禁未经容灾兜底直接调用 Chrome 76+ 才提供的 ES2019–ES2022 标准库方法如 `Promise.allSettled`，且类型检查器 SHALL 在编译期拦截此类高版本 API 调用）；系统在 HTML 入口层 MUST 挂载全局异常与 Promise 拒绝监听器，当脚本加载解析失败或初始化过程抛出致命未捕获异常时，系统 SHALL 立即在屏幕上呈现高对比度的可视化错误诊断面板，显示异常详情与调用堆栈，严禁呈现没有任何反馈的纯黑卡死。

#### Scenario: 较旧内核 WebView 启动正常挂载应用
- **WHEN** 用户在运行 Chrome 70+ / Android 10 级别内核的移动设备上启动应用
- **THEN** 静态资源正常解析执行，React 根节点顺利挂载并进入双路视频导入首屏

#### Scenario: 低于 Chrome 76 内核选完本地视频回跳应用不崩溃
- **WHEN** 用户在坚果 R2（Android 10，系统 WebView 低于 Chrome 76、缺少 `Promise.allSettled` 与 `file.arrayBuffer`）上点击「视频1」或「视频2」选取本地 MP4 视频并返回应用
- **THEN** 应用顺利完成乐观挂载、视频元数据探测与音频解析兜底，不抛出 `TypeError: Promise.allSettled is not a function` 或弹出崩溃诊断面板，正常进入就绪状态

#### Scenario: 编译期拦截高版本标准库 API 调用
- **WHEN** 开发者在前端源码中误引入 ES2019 及以上标准库方法（如 `Promise.allSettled`、`Object.fromEntries`、`String.prototype.replaceAll`）并执行类型检查与构建命令
- **THEN** `tsc` 编译检查立即报错阻断构建，不依赖运行时真机才暴露缺陷

#### Scenario: 启动阶段发生未捕获致命错误触发兜底展示
- **WHEN** 应用启动时静态资源加载超时或第三方环境缺少必要 API 导致致命脚本异常
- **THEN** 页面自动呈现包含错误标题、具体信息和堆栈的深底红字诊断面板，方便用户截图排查定位

### Requirement: 老旧内核 CSS 安全区特性查询隔离回退
系统在全界面容器（包括顶部导航、工作区舞台、底部控制栏、导入舞台、空间标定舞台、对比台画布容器及导出网格）中应用包含 CSS 自定义变量的安全区边距函数（如 `max(..., var(--safe-*))`）时，MUST 将其包裹在 CSS `@supports (padding: max(0px))` 特性查询内，并在特性查询之外保留固定像素静态边距声明；严禁在无特性查询隔离的情况下让老旧 Chromium（`< 79`）内核执行含 `var()` 的 `max()` 表达式而触发 IACVT 归零。

#### Scenario: Chrome 74 级别 WebView 渲染全应用边距
- **WHEN** 应用在内置 Chrome 74 级别 System WebView 的 Android 10 设备上冷启动并依次切换至「导入」「视频1」「视频2」「对比台」「导出片段」页面
- **THEN** 所有主容器与操作栏的左右及底部计算内边距均保持预设固定像素回退值（非 `0px`），卡片、时间轴与操作按钮不紧贴屏幕边缘或系统导航栏

#### Scenario: 现代 Chrome 79+ 内核保留安全区避让叠加
- **WHEN** 应用在支持 `max()` 与 `env(safe-area-inset-*)` 的现代移动设备或模拟器上横屏运行
- **THEN** `@supports (padding: max(0px))` 规则块正常生效，各容器在静态最小边距与系统安全区宽度之间取较大值完成避让

### Requirement: 跨代兼容 Flex 间距与 16:9 窄横屏布局零溢出
系统在全部 Flexbox 容器中 MUST 采用不依赖 Chrome 84+ Flexbox `gap` 属性的间距实现（统一通过子元素邻接外边距控制横纵向间距），确保 Chrome 70~83 内核中所有按钮、图标与徽章间距清晰不粘连；在逻辑宽高 `640×360` 叠加 `48px` 侧边三键导航安全区的经典 16:9 窄横屏下，全部步骤的控件 MUST 完整位于安全视口内，严禁横向或纵向溢出截断。

#### Scenario: Chrome 74 下全应用 Flex 按钮与标签间距有效
- **WHEN** 应用在 Chrome 74 级别 Android 10 WebView 上渲染导入页、标定页、对比台及导出页
- **THEN** 顶部步骤导航、通道卡片徽章、按钮内部图标与文本以及底栏控件组之间均具备非零像素间距，不发生 0px 贴连

#### Scenario: 640x360 窄横屏叠加三键导航全界面零溢出
- **WHEN** 应用在 `640×360` 逻辑视口且右侧存在 `48px` 安全区的设备横屏依次切换各页面（含叠加模式）
- **THEN** 页面不出现横向或纵向滚动截断，所有按钮与控件右边界均不越过可用安全区右边界

### Requirement: Android 原生系统栏纯黑锁定与存储文件兼容
原生 Android 主题配置 MUST 显式将 `statusBarColor` 与 `navigationBarColor` 锁定为纯黑，避免老版本 ROM 浅色主题在系统导航栏显示浅色白条；`AndroidManifest.xml` 中 `WRITE_EXTERNAL_STORAGE` 权限 `maxSdkVersion` MUST 覆盖至 API 29（Android 10），配合 Android 10+ 分区存储 `MediaStore` 与 Android 6~9 运行期权限申请保障全版本原生写入公开相册目录成功；纯 Web 调试环境下保留 `accept="video/*"` 文件输入框。

#### Scenario: 老版本 Android 原生主题导航栏与存储权限检查
- **WHEN** 查看 Android 主题样式及 Manifest 配置并在 Android 6~10 设备导入并导出视频
- **THEN** 状态栏与导航栏背景配置为纯黑，系统可通过原生持久化 URI 访问视频，并将导出结果写入公开相册或 `Movies` 目录且零权限异常

### Requirement: 通道持久化 URI 授权按需释放
在 Android 原生平台下，当用户为 视频1 或 视频2 更换新视频或应用插件实例销毁时，系统 MUST 释放此前为该通道申请的持久化 URI 读取权限；若另一通道当前仍引用同一个 URI，则 MUST 保留该共享 URI 的读取权限直到其也被替换或销毁。

#### Scenario: 更换单通道视频后释放旧 URI 授权
- **WHEN** 用户在 视频1 选择视频 A，随后更换选择视频 B（且 视频2 未使用视频 A）
- **THEN** 系统释放视频 A 的持久化 URI 读取权限并仅保留当前活跃通道所需权限，不会随长期反复选片累积系统权限配额

#### Scenario: 双通道选用同一视频时更换一侧不误释放
- **WHEN** 用户在 视频1 和 视频2 均选择视频 A，随后将 视频1 更换为视频 B
- **THEN** 系统保留 视频2 对视频 A 的读取权限，视频2 的预览、音频分析与后续导出仍正常可用

### Requirement: 未消费音频分析载荷覆盖清理
在 Android 原生平台下，当多次连续触发音频分析或通道已切换新视频时，本地代理服务 MUST 覆盖并清理前一次尚未被前端读取的临时音频 PCM 内存载荷，避免未消费的音频数据滞留内存。

#### Scenario: 连续选片覆盖前次未消费的音频载荷
- **WHEN** 用户快速更换同一通道视频或重复触发音频提取，前一次提取的 PCM 数据尚未被前端读取
- **THEN** 系统清理旧音频载荷的索引与内存引用，仅保留最新一次有效提取载荷

### Requirement: Web 端导入 Object URL 释放
在纯 Web 浏览器环境下，当用户在导入步骤为 视频1 或 视频2 更换本地视频文件时，系统 MUST 撤销释放该通道此前生成的旧预览对象 URL（`blob:` URL），防止重复换片导致浏览器堆内存持续增长。

#### Scenario: Web 端重复更换视频释放旧预览链接
- **WHEN** 用户在纯 Web 浏览器调试环境下为 视频1 导入视频 1 后，再次点击 视频1 更换为视频 2
- **THEN** 视频 1 对应的旧 `blob:` 预览 URL 被撤销释放，不再持续占用浏览器对象 URL 引用

### Requirement: 单视频同屏空间时间一体标定与只读状态小点指示
单视频标定步骤（「视频1」与「视频2」）MUST 在同一页面内同屏同时展示空间三线标尺视频舞台与底部时间波形/截取/锚点/BPM 面板，共用同一个 `<video>` 实例与实时时间游标，免除跨子模式来回切换；界面严禁弹出任何引导弹窗或强制禁用步骤跳转；顶栏保留 `空间` 与 `时间` 状态小点指示容器（拖动过任一三线后亮起空间点、点击「设为锚点」后亮起时间点），该状态小点组件仅用于只读视觉指示，不再响应点击切换事件，旁侧提供显式「下一步」按钮。

#### Scenario: 空间与时间同屏协同标注无需切换
- **WHEN** 用户进入「视频1」标定步骤
- **THEN** 视频画幅内可直接拖拽三条空间定线，同时底部面板呈现完整波形、截取手柄、`设为锚点` 与 `TAP/BPM` 控制，用户在波形上按住滑动或点击找帧时空间标线实时叠加在当前视频帧上

#### Scenario: 只读状态小点独立点亮与显式下一步推进
- **WHEN** 用户在「视频1」页拖拽任一三线标尺并点击「设为锚点」后，尝试点击顶栏「空间/时间」状态指示或点击「下一步」按钮
- **THEN** 「空间」与「时间」对应的状态小点相继由暗点亮；点击「空间/时间」状态小点本身不切换视图或遮罩任意层；无任何引导提示弹窗打断操作，点击「下一步」直接跳转至「视频2」步骤（在「视频2」点击「下一步」跳转至「对比台」）

#### Scenario: 未完成标定时不拦截跳转
- **WHEN** 用户在「视频1」页未拖动任何三线或未点击「设为锚点」，直接点击「下一步」或顶栏「对比台」
- **THEN** 对应状态小点保持未点亮状态，系统正常跳转进入目标步骤且不弹出阻止或警告对话框

### Requirement: 顶栏软件图标入口与设置页无损切入返回
顶部全局导航栏「导入」左侧 MUST 放置可点击的软件图标按钮，并与后续操作按钮用一条灰色竖线隔开。点击该图标后顶栏保持可见且图标呈现激活态，下方主工作区切换至「设置与关于」页面；再次点击软件图标、点击设置页「返回」按钮或点击顶栏任意可用步骤时，系统返回对应工作流视图并完整保留已导入视频与全部标定状态。

#### Scenario: 从任意步骤切入设置页再无损返回
- **WHEN** 用户已导入两路视频并处于「视频1」或「对比台」页面，点击顶栏最左侧软件图标进入设置与关于页，随后点击页面「返回」按钮或再次点击软件图标
- **THEN** 界面恢复进入设置页之前的工作步骤，两路视频及其空间三线、锚点与 BPM 状态完整保留不重置

#### Scenario: 从设置页直接点击顶栏可用步骤跳转
- **WHEN** 用户在设置与关于页中点击顶栏中已解锁的步骤选项卡（如「对比台」）
- **THEN** 系统退出设置页并直接切换至对应目标步骤视图
