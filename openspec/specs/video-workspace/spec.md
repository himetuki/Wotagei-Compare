# video-workspace Specification

## Purpose

提供 Wotagei-Compare 应用基础工作区底座，负责跨平台原生环境下的强制横屏锁定、双路视频导入与状态持久化、全屏线性三线对齐向导流转、播放工作台主布局以及单项快速微调通道。

## Requirements

### Requirement: 全程强制横屏锁定与界面适配
系统在移动端原生与浏览器环境下运行时，MUST 强制锁定为横屏（Landscape）方向，所有向导步骤与播放页面 SHALL 针对横屏视口进行无黑边拉伸的自适应布局。

#### Scenario: 移动设备启动或旋转屏幕
- **WHEN** 用户在移动设备上启动应用或物理旋转设备至竖屏方向
- **THEN** 系统保持横屏显示方向锁定，界面元素按横屏宽高比自适应排布

### Requirement: 双路本地视频文件导入与状态持久驻留
系统 MUST 支持用户在导入步骤中分别选择并载入两个本地视频文件并展示分辨率、时长与检测 BPM，导入页不设初始对比模式切换或演示样本生成按钮；双通道槽位统一标记为「CH1」与「CH2」，严禁使用「基准源」「对比源」等定性称谓；用户选取文件后，系统 MUST 立即将槽位更新为已就绪并展示文件信息，严禁在等待媒体元数据期间保持无响应的「未载入」；在 Android 原生平台下，系统 MUST 通过系统原生视频文件选择器获取持久化 `content://` URI 及支持随机寻道的本地流式预览 URL，并通过原生流式音频解码提取单声道 PCM 数据进行波形与 BPM 测算，彻底消除超过 80MB 大视频被跳过音频解析的截断限制，严禁通过 WebView 沙盒全量读取大文件内存；在纯 Web 浏览器环境下保持 `<input type="file">` 与安全降采样探测逻辑（含 ≤ 2.5s 元数据超时保底与 >80MB Web 内存保护）；系统中的底层视频支撑节点 MUST 保持在浏览器渲染管线中活跃（严禁使用 `display: none` 导致 GPU 纹理断流），且全界面 CSS 边距在老旧内核下 MUST 具备固定数值回退保障；只要用户不主动更换视频，其几何与音频参数 SHALL 永久保留在内存中，在任意步骤间跳转时严禁丢失已导入的视频。

#### Scenario: 首页切换模式保留视频
- **WHEN** 用户导入两个视频并进入后续标定或对比工作台后，再次切回导入步骤查看
- **THEN** 系统完整保留两个视频的引用、几何标定与音频参数，不发生视频丢失或重置，且槽位仅标识为 CH1 与 CH2，无基准源/对比源文案

#### Scenario: 用户选取视频后获得即时视觉响应
- **WHEN** 用户在 Android 原生应用中通过系统原生视频选择器选取本地 MP4 视频并返回应用
- **THEN** 应用获得持久化 `content://` URI 与本地流式预览 URL，对应通道槽位立即呈现文件名与视频参数，主操作按钮在双通道均选定后即可解锁

#### Scenario: 老旧内核或元数据解析异常触发超时保底
- **WHEN** 运行在 Web 浏览器或老旧 WebView 内核上的设备因媒体元素限制未触发或延迟触发 `loadedmetadata` 事件
- **THEN** 系统在 2.5 秒内自动采用标准分辨率（1920×1080）与保底时长，顺利完成视频注册并消除阻塞，允许用户正常推进向导

#### Scenario: 大尺寸视频文件导入触发内存防崩保护
- **WHEN** 用户在纯 Web 浏览器调试环境下导入文件体积超过 80MB 的高码率高清视频文件
- **THEN** 系统跳过全量 PCM 解码以保护 WebView 堆内存，采用安全预设 BPM（160 BPM）与快速音轨占位，杜绝进程 OOM 崩溃闪退

#### Scenario: Android 原生平台导入超过 80MB 大视频完整解析波形与音轨
- **WHEN** 用户在 Android 原生应用中选取文件体积大于 80MB 的高清本地视频文件
- **THEN** 系统通过原生流式解码提取音频 PCM 并完成真实波形与 BPM 测算，不发生 WebView 堆内存溢出闪退，且后续导出单侧原声时具备完整有效音频

#### Scenario: 老旧内核 Canvas 视频纹理持续刷新
- **WHEN** 用户在运行老旧 Chromium 内核的设备上进入对比工作台或导出预览
- **THEN** 底层视频支撑节点在保持视觉隐蔽的同时维持活跃渲染树挂载，Canvas 能持续正确获取最新解码视频帧，不出现画面黑屏或首帧冻结

### Requirement: 线性全屏向导状态流转
系统 MUST 支持按「导入 → CH1 空间标定 → CH2 空间标定 → CH1 时间标定 → CH2 时间标定 → 对比台 → 导出片段」的顺序推进全屏标定与对比导出，过程中单视频 SHALL 占满横屏主视口以保证最高标定精度。

#### Scenario: 依序完成向导进入播放工作台
- **WHEN** 用户完成双路视频导入、两视频的三线空间标定以及两视频的时间区间截取与音频对拍锚点设定
- **THEN** 系统进入同台对比播放工作台并加载双方对齐参数

### Requirement: 模式无缝切换与单项快速微调
系统 MUST 在顶部导航栏提供统一的全局步骤分段直达条，彻底移除所有数字标号（`01`~`06`），采用纯精炼短标签命名（`导入` / `CH1空间` / `CH2空间` / `CH1时间` / `CH2时间` / `对比台` / `导出片段`），确保在移动端横屏狭窄视口下严禁挤占导航空间；当双视频载入后允许用户在任意环节一键直达目标步骤微调参数，对比工作台初始默认进入左右分区模式，并支持无缝切换左右分区与半透明叠加模式。

#### Scenario: 快速微调单项参数
- **WHEN** 用户在对比工作台点击顶部步骤条中的「CH2时间」
- **THEN** 系统直接切换至 CH2 时间标定视图并展示既有参数与截取区间，修改后点击顶部「对比台」或确认按钮即刻返回工作台

#### Scenario: 初始进入工作台默认左右分区
- **WHEN** 用户完成标定首次进入对比播放工作台
- **THEN** 系统默认以左右分区模式呈现双视频对比画面

### Requirement: 对比播放工作台交互与重新标定
播放工作台 MUST 提供沉浸式横屏视口，顶部集成全局步骤分段直达条、对比模式分段切换、声音源选择、独立镜像开关与导出入口，底部集成统一时间轴、锚点复位、播放/暂停、逐帧微调、七档慢放切换及叠加透明度滑块，彻底移除冗余的「退出」「重新向导」按钮与微调下拉框；在工作台与「导出片段」或其他向导步骤相互切换时，系统 MUST 保持底层视频解码节点及播放时钟的可用性与自愈性，严禁出现视频黑屏、画面不可见或控制器与新节点脱节卡死。

#### Scenario: 用户请求重新标定
- **WHEN** 用户在播放工作台点击顶部步骤条的「视频1空间」
- **THEN** 系统保留当前已载入的双视频引用，并直接切换至视频 1 空间标定视图

#### Scenario: 对比台与导出片段反复切换画面持久展示
- **WHEN** 用户在对比工作台点击「导出片段」进入导出视图后，点击返回按钮或点击顶部导航栏中的「对比台」切回对比工作台
- **THEN** 对比工作台主画布立即呈现对应的双通道视频画面，视频解码节点与 Canvas 渲染保持可用，不出现黑屏、画面不可见或播放/暂停控制失效

#### Scenario: 切换至前期步骤再返回对比台画面正确展示
- **WHEN** 用户从对比工作台切换至「CH1空间」「CH2空间」「CH1时间」或「CH2时间」等前置步骤微调后，再次点击「对比台」
- **THEN** 对比工作台自动重新完成视频节点与同步引擎的绑定与初相定位，主画布完整呈现当前时间戳的双通道对比画面，播放与逐帧微调功能正常可用

### Requirement: 专业影视监视器极简暗黑视觉规范
系统全界面 MUST 采用纯黑与深炭灰底色、单一高对比主强调色、全矢量几何图标与等宽数字时间码，严禁在任何视图中渲染 Emoji 字符、无交互功能的装饰性文字（彻底移除 WC-MON 标识）；系统顶栏右侧在非对比台步骤中严禁残留或渲染黄色操作按钮；顶部导航栏右上角的 `CH1 …… BPM` 与 `CH2 …… BPM` 徽章仅在「对比台」步骤展示，在其他步骤（导入、空间、时间）中彻底隐藏；在空间标定步骤中，顶栏右侧承载三线模型下拉菜单与镜像开关；全软件界面统一采用 `CH1` 与 `CH2`，彻底移除 `视频 1`、`视频一`、`CH 01`、`CH 02` 等冗余命名。

#### Scenario: 界面纯净度与图标检查
- **WHEN** 用户浏览导入页、空间标定页、时间标定页、对比工作台及导出页
- **THEN** 界面仅呈现矢量图标、精炼控件标签与等宽时间码，左上角不显示 WC-MON，顶栏右侧在非对比台步骤不显示 BPM 徽章（对比台常驻显示且支持点击修改），全界面通道标识严格为 CH1 与 CH2

#### Scenario: 狭窄横屏视口零截断检查
- **WHEN** 用户在可用逻辑宽度仅 650px~850px 的横屏设备（含侧边金刚键）上浏览各视图
- **THEN** 无数字标号的顶栏步骤按钮、顶栏右侧控件以及各视图底部操作面板均完整展示，不被挤出屏幕边缘，不发生截断

#### Scenario: 全流程任意位置点击顶栏修改 BPM
- **WHEN** 用户在对比工作台中点击顶栏右上角的「CH1 188 BPM」徽章
- **THEN** 系统激活手动数值输入，用户输入新数值并确认后，系统立即更新对应通道的基准 BPM 并同步重算所有关联时间轴与节拍刻度（在非对比台步骤中顶栏不显示该徽章）

### Requirement: 系统状态栏与虚拟金刚键安全区避让
系统 MUST 在横屏运行时主动避让操作系统的常驻状态栏（Status Bar）、虚拟按键导航栏（经典金刚键，Navigation Bar）及屏幕物理缺口（Display Cutout）；原生工程 MUST 将窗口背景配置为纯黑并开启打孔屏短边全屏延伸（`shortEdges`），严禁在打孔避让时露出浅色系统底色；应用底色全屏铺满的同时，全部导航步骤选项卡、操作按钮、时间轴控件、状态指示徽章及有效交互区域 SHALL 通过 CSS 安全区变量约束在设备物理安全区域内，严禁与系统级按键或状态栏发生物理遮挡与点击误触。

#### Scenario: 包含常驻状态栏的横屏设备渲染
- **WHEN** 用户在开启常驻状态栏的移动设备上横屏运行应用
- **THEN** 系统顶部全局导航栏自动向下收缩状态栏对应的高度边距，导航栏内的文字、步骤标签与操作按钮完全显示在状态栏下方，不产生文字与图标重叠

#### Scenario: 包含经典金刚键（三键导航）的设备横屏运行
- **WHEN** 用户在右侧常驻金刚键导航栏的 Android 设备上横屏运行应用
- **THEN** 系统所有视图的右侧边界自动向内缩进金刚键对应宽度，全局导航栏最右侧的「下一步」按钮、BPM 徽章及工作台右侧控件均显示在金刚键左侧安全区，点击「下一步」时不触发系统返回或桌面导航键

#### Scenario: 底部控制栏避让底部虚拟按键或手势条
- **WHEN** 用户处于空间标定、音频对拍或对比工作台等包含底部控制栏的视图
- **THEN** 底部控制栏内容区域自动向上增加安全边距，播放按钮、步进微调按钮及时间轴进度条完全脱离底部系统手势指示条与虚拟按键冲突区域

#### Scenario: 打孔/刘海全面屏横屏运行零白边
- **WHEN** 用户在带有前置摄像头打孔或刘海缺口的 Android 设备上横屏运行应用
- **THEN** 应用主窗口向屏幕两侧短边无缝延展铺满，不产生任何原生浅色避让白边，缺口侧的内容依据 `env(safe-area-inset-left)` 保持合理内边距

### Requirement: 移动端运行时语法兼容与首屏致命异常自诊断展示
构建打包产物 MUST 兼容现代主流及稍旧内核（Chrome 70+）的 Android System WebView，不仅在构建层支持 ES2018 语法标准，应用源码在标准库调用上 MUST 严格遵守 ES2018 运行时边界（严禁未经容灾兜底直接调用 Chrome 76+ 才提供的 ES2019–ES2022 标准库方法如 `Promise.allSettled`，且类型检查器 SHALL 在编译期拦截此类高版本 API 调用）；系统在 HTML 入口层 MUST 挂载全局异常与 Promise 拒绝监听器，当脚本加载解析失败或初始化过程抛出致命未捕获异常时，系统 SHALL 立即在屏幕上呈现高对比度的可视化错误诊断面板，显示异常详情与调用堆栈，严禁呈现没有任何反馈的纯黑卡死。

#### Scenario: 较旧内核 WebView 启动正常挂载应用
- **WHEN** 用户在运行 Chrome 70+ / Android 10 级别内核的移动设备上启动应用
- **THEN** 静态资源正常解析执行，React 根节点顺利挂载并进入双路视频导入首屏

#### Scenario: 低于 Chrome 76 内核选完本地视频回跳应用不崩溃
- **WHEN** 用户在坚果 R2（Android 10，系统 WebView 低于 Chrome 76、缺少 `Promise.allSettled` 与 `file.arrayBuffer`）上点击「CH1」或「CH2」选取本地 MP4 视频并返回应用
- **THEN** 应用顺利完成乐观挂载、视频元数据探测与音频解析兜底，不抛出 `TypeError: Promise.allSettled is not a function` 或弹出崩溃诊断面板，正常进入就绪状态

#### Scenario: 编译期拦截高版本标准库 API 调用
- **WHEN** 开发者在前端源码中误引入 ES2019 及以上标准库方法（如 `Promise.allSettled`、`Object.fromEntries`、`String.prototype.replaceAll`）并执行类型检查与构建命令
- **THEN** `tsc` 编译检查立即报错阻断构建，不依赖运行时真机才暴露缺陷

#### Scenario: 启动阶段发生未捕获致命错误触发兜底展示
- **WHEN** 应用启动时静态资源加载超时或第三方环境缺少必要 API 导致致命脚本异常
- **THEN** 页面自动呈现包含错误标题、具体信息和堆栈的深底红字诊断面板，方便用户截图排查定位

### Requirement: 老旧内核 CSS 安全区特性查询隔离回退
系统在全界面容器（包括顶部导航、工作区舞台、底部控制栏、导入舞台、空间标定舞台、对比台画布容器及导出网格）中应用包含 CSS 自定义变量的安全区边距函数（如 `max(..., var(--safe-*))`）时，MUST 将其包裹在 CSS `@supports (padding: max(0px))` 特性查询内，并在特性查询之外保留固定像素静态边距声明；严禁在无特性查询隔离的情况下让老旧 Chromium（`< 79`）内核执行含 `var()` 的 `max()` 表达式而触发 IACVT 归零。

#### Scenario: Chrome 74 级别 WebView 渲染全应用边距
- **WHEN** 应用在内置 Chrome 74 级别 System WebView 的 Android 10 设备上冷启动并依次切换至「导入」「CH1空间」「CH1时间」「对比台」「导出片段」页面
- **THEN** 所有主容器与操作栏的左右及底部计算内边距均保持预设固定像素回退值（非 `0px`），卡片、时间轴与操作按钮不紧贴屏幕边缘或系统导航栏

#### Scenario: 现代 Chrome 79+ 内核保留安全区避让叠加
- **WHEN** 应用在支持 `max()` 与 `env(safe-area-inset-*)` 的现代移动设备或模拟器上横屏运行
- **THEN** `@supports (padding: max(0px))` 规则块正常生效，各容器在静态最小边距与系统安全区宽度之间取较大值完成避让

### Requirement: 跨代兼容 Flex 间距与 16:9 窄横屏布局零溢出
系统在全部 Flexbox 容器中 MUST 采用不依赖 Chrome 84+ Flexbox `gap` 属性的间距实现（统一通过子元素邻接外边距控制横纵向间距），确保 Chrome 70~83 内核中所有按钮、图标与徽章间距清晰不粘连；在逻辑宽高 `640×360` 叠加 `48px` 侧边三键导航安全区的经典 16:9 窄横屏下，全部步骤的控件 MUST 完整位于安全视口内，严禁横向或纵向溢出截断。

#### Scenario: Chrome 74 下全应用 Flex 按钮与标签间距有效
- **WHEN** 应用在 Chrome 74 级别 Android 10 WebView 上渲染导入页、标定页、对比台及导出页
- **THEN** 顶部步骤导航、通道卡片徽章、按钮内部图标与文本以及底栏控件组之间均具备非零像素间距，不发生 0px 贴连

#### Scenario: 640x360 窄横屏叠加三键导航全界面零溢出
- **WHEN** 应用在 `640×360` 逻辑视口且右侧存在 `48px` 安全区的设备横屏依次切换各页面（含叠加模式）
- **THEN** 页面不出现横向或纵向滚动截断，所有按钮与控件右边界均不越过可用安全区右边界

### Requirement: Android 原生系统栏纯黑锁定与存储文件兼容
原生 Android 主题配置 MUST 显式将 `statusBarColor` 与 `navigationBarColor` 锁定为纯黑，避免老版本 ROM 浅色主题在系统导航栏显示浅色白条；`AndroidManifest.xml` 中 `WRITE_EXTERNAL_STORAGE` 权限 `maxSdkVersion` MUST 覆盖至 API 29（Android 10），配合 Android 10+ 分区存储 `MediaStore` 与 Android 6~9 运行期权限申请保障全版本原生写入公开相册目录成功；纯 Web 调试环境下保留 `accept="video/*"` 文件输入框。

#### Scenario: 老版本 Android 原生主题导航栏与存储权限检查
- **WHEN** 查看 Android 主题样式及 Manifest 配置并在 Android 6~10 设备导入并导出视频
- **THEN** 状态栏与导航栏背景配置为纯黑，系统可通过原生持久化 URI 访问视频，并将导出结果写入公开相册或 `Movies` 目录且零权限异常
