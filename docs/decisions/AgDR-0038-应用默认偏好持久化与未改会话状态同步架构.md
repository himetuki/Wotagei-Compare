# 应用默认偏好持久化、顶栏图标入口与未改会话状态同步架构

> 在【每次冷启动应用都需要重复调整三线模型、对比模式、音源、BPM 策略、慢放倍速与步进粒度，且需要在顶部「导入」左侧放置软件图标入口】的处境下，面对【设置页如何切入返回才不丢失已导入视频、以及修改默认项后对当前会话如何生效】的顾虑，我决定【在顶栏保持可见的前提下通过顶栏图标切换 `view-body` 渲染独立的「设置与关于」页面，将 7 项默认偏好以扁平 JSON 持久化到 `localStorage`，并在 `App.tsx` 统一托管可跨页保留的偏好与会话脏标志以实时同步未手动改动的当前会话状态】，以达成【设置随手进出且零丢片、重启持久生效、当前未改动工作流即时跟随】的目标，并接受【将原本局部驻留在 `Workbench.tsx` 的声音源、倍速、步进粒度及自定义步数提升至 `App.tsx` 状态管理的轻微状态上移】的代价。

## 考虑过的方案

| 方案 | 好处 | 代价 |
| --- | --- | --- |
| **方案 A（入选）：保留顶栏，图标点击切换主区为设置页 + `localStorage` 持久化 + `App.tsx` 脏标志实时同步未改状态** | 随时点击图标或任意顶栏步骤一键往返，已导入的双路视频、`blob:`/`content://` 引用、三线与锚点完全保留在 `App.tsx`；偏好上移后从对比台切出再返回时还能顺带记忆当前音源/倍速/步长 | 需把声音源、倍速、步长预设与自定义步数由 `Workbench` 局部状态上移至 `App.tsx`，并记录各字段是否被用户手动改动过 |
| **方案 B：全屏弹窗/独立路由覆盖顶栏，且默认偏好仅下次重启才生效** | 无需跟踪当前会话脏标志 | 无法用顶栏步骤条直达返回；用户在「导入」页顺手改了默认对比模式或默认音源后，本轮接着标定进对比台却不生效，体验割裂反直觉 |
| **方案 C：修改默认偏好后无条件强制覆盖当前会话所有状态** | 逻辑最简单，不用维护脏标志 | 若用户已经在对比台专门把声音切换成「视频2」或调成 `0.3x` 慢放，去设置页顺手改别的参数时会被意外重置 |

## 决定

选 **方案 A**，因为：
1. **无损单根状态树**：Wotagei-Compare 的双路视频句柄（含 `File`、`blob:` URL、Android `nativeUri` 与异步解码 `audioInfo`）均托管在 `App.tsx`。将设置页作为 `App.tsx` 主视图层的一个切换分支（而非刷新或新建顶层壳），可保证进出设置页时零内存泄漏、零视频重载；
2. **直觉一致的实时生效边界**：对每个偏好项维护轻量布尔标志（`sessionEdited`，仅在标定/对比台实际被用户显式修改时置 `true`）。用户在导入前或尚未进入对比台时调整默认偏好，由于对应字段尚未被会话手改，后续步进直接自然继承新默认值；已在对比台手动调试中的状态则受保护不被打断；
3. **消除 `Workbench` 重挂载丢状态**：将 `soundSource`、`slowMotionRate`、`stepPreset`、`customStepSec` 提升到 `App.tsx`，顺带避免了对比台切去微调 `视频1` 再切回时音源和倍速重置回默认值的问题。

## 代价

- 我们接受：`App.tsx` 新增轻量偏好状态、会话脏标志集合及跨子组件回调；
- 我们放弃：需要单独返回键的全屏遮罩设置页，以及仅重启后生效的延迟配置模型；
- 后面要还的债：若未来设置项大幅膨胀，可再按域拆分 `sessionEdited` 结构；当前 7 个扁平字段直接用字面量对象管理最简洁，不引入复杂状态库。

## 什么情况下需要重新讨论

- 如果未来支持多项目草稿存档且每个项目独立保存工作台播放参数，需要区分「全局出厂默认」与「项目级上次状态」两层覆盖优先级。
