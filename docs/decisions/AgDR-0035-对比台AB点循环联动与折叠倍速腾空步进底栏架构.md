# 对比台AB点循环联动与折叠倍速腾空步进底栏架构

> 在对比台需要升级为“现场扣技复读机”（新增 A-B 点局部循环播放 + 暂停态多粒度前后步进微调）且顶部梯形折叠拉手过于隐蔽的处境下，面对 640×360 窄横屏底栏可用宽度仅约 590px、现有 7 档平铺倍速按钮已将底栏填满的顾虑，我决定：
> 1. 复用 [DualVideoSyncEngine](../../src/core/sync-engine.ts) 已有的 `loopInterval` 与节拍器双向锁相能力，在对比台时间轴行新增 `A`/`B` 设点与清除控件并高亮选区，且将该 A-B 区间作为初始默认区间继承给「导出片段」；
> 2. 将底栏第二行平铺的 7 档慢放倍速按钮收敛为向上弹出的紧凑选择菜单（如 `1.0x ▾`，交互模式与 `SYNC BPM` 菜单一致），用释放出来的 ~180px 横向空间容纳 `<` / `>` 步进按钮及向上弹出的步长菜单（时间档 `1帧 0.033s / 0.05s / 0.1s`、拍分档 `1/4拍 / 1/2拍` 与自定义数值输入）；
> 3. 步进寻道采用内存目标时间 `tauRef` 即时累加后调用引擎静态寻道，按下步进自动暂停，确保高速连击不丢步；
> 4. 适当放大顶部中央梯形抽屉拉手尺寸但保持零文字纯几何外观，增强默认收起状态下的可发现性；
> 以达成窄横屏底栏零溢出、现场扣技微操极度顺手、且与导出无缝打通的目标，并接受切换倍速从单次点击变为两次点击（打开菜单再选档）的代价（部分取代 AgDR-0009 中移除步进按钮的决定）。

## 考虑过的方案

| 方案 | 好处 | 代价 |
| --- | --- | --- |
| **方案 A（入选）：将 7 档倍速收成向上弹出菜单，步进与步长常驻底栏第二行** | 一次性释放 ~180px 横向宽度，640×360 窄横屏彻底不溢出；扣技高频使用的 `<` `>` 步进一触即达，连点顺滑不遮挡视频画幅；复用 `SYNC BPM` 已有交互范式 | 切换 0.1x~1.0x 倍速需点开菜单选择（2 次点击而非 1 次） |
| **方案 B：保持 7 档倍速常驻平铺，把步进或 AB 塞入画布悬浮胶囊或折叠工具栏** | 保留单次点击换倍速 | 画布悬浮遮挡舞者脚部动作；放进顶部折叠工具栏则离底栏播放键太远、高频微调动作必须反复抬头点顶部再看底栏，极度割裂 |
| **方案 C：仅依赖 `video.currentTime ± step` 直接做步进** | 实现看似简单 | 在老旧手机上连续快点 3 次「下一帧」时前次异步 seek 未结束，`currentTime` 仍是旧值，会导致严重丢步/只跳 1 步 |

## 决定

选 **方案 A + 目标时间累加步进**，因为：
1. **高频 vs 低频分离**：在现场扒技时，“定好 0.2x 或 0.3x 后一直按前进/后退步进抠动作、按 A/B 反复练”的频次远高于“每秒钟切换一次倍速”。把中低频的 7 档倍速收进紧凑弹窗、把最高频的步进和 A/B 放到主底栏，完全符合空间效用最大化原则；
2. **闭环复用零重复造轮子**：对比台接入 `loopInterval` 与已有导出预览完全同源，且把对比台抠好的 `[A, B]` 直接带入导出页，消灭了“在对比台练完一遍、进导出页还得重新找一遍 A/B 点”的重复劳动；
3. **HTML5 帧率无关的通用微操**：由于手机视频混杂 24/30/60fps 且 BPM 对齐引入了双侧速率差，提供「时间步长 + 随 BPM 换算的拍分步长 + 自定义输入」既能逐帧定格看轨迹，又能按 `1/4 拍` 对节奏，比写死单一帧率更科学；
4. **不违背极简监视器风格**：梯形拉手仅放大触控面积与几何存在感、不贴任何导引文字，兼顾美观与可发现性。

## 代价

- 我们接受：调节慢放倍速需要点一下当前倍率胶囊展开菜单再点目标倍率；
- 我们接受：若对比台外层交集区间因上游修改标定或 BPM 策略发生变化，已设置的 A-B 区间需自动夹紧或超出失效时安全清除；
- 后面要还的债：本决策实施完成后，需将 [AgDR-0009](AgDR-0009-移动端同台对比交集时间轴与沉浸监看交互重构.md) 中“放弃保留步进微调按钮”的条款标记为被本记录部分取代。

## 什么情况下需要重新讨论

- 如果后续实测发现用户需要在对比台高频单指盲切倍速（如在 0.2x 与 1.0x 间瞬切），可再评估在倍速胶囊旁增加双击/快捷切换能力。
