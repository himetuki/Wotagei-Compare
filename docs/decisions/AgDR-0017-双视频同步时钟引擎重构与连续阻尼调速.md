# 双视频同步时钟引擎重构与连续阻尼调速

> 在对比播放工作台（Workbench）与导出预览页（ExportPage）中，面对底层 HTMLVideoElement 的寻道队列防抖、冷却隔离、起播就绪与锁相环微调逻辑重复散落在各 React 视图组件内且二值化调速（1.08/0.92）缺乏平滑阻尼的问题，我决定抽离独立的纯 TypeScript 核心引擎 `DualVideoSyncEngine`（内聚 `SafeVideoController` 寻道队列、连续阻尼比例调速控制器与统一时钟循环），以达成视图层胶水代码清零、调速连续丝滑无感、双端绝对对齐的目标，并接受增加一层引擎状态订阅与接口适配的代价。

## 考虑过的方案

| 方案 | 好处 | 代价 |
| --- | --- | --- |
| 方案 A：直接引入第三方库（如 timingsrc 或 media-element-syncer） | 无需编写底层同步算法代码 | 现有库均只面向 1:1 等长视频，无法处理本项目的非对称 BPM 速率缩放比（$r_1 \neq r_2$）、锚点差值（$\tau$ 映射）与交集区间循环，且包体积和社区维护不可控 |
| 方案 B：保持在 React 组件内部封装 Custom Hook（如 `useDualVideoSync`） | 依然留在 React 上下文中，改动直观 | 无法脱离 React 渲染生命周期独立进行严密的算法单元验证；导出离线管线或其他非 UI 环节无法复用 |
| 方案 C（本方案）：独立纯 TS 领域引擎 `DualVideoSyncEngine` | 关注点彻底分离；引擎零 UI 依赖，可被任意组件或离线脚本直接实例化并支持高覆盖率自动化验证；内聚排队寻道、阻尼调速与就绪栅栏；全面消除视图组件数百行胶水冗余 | 视图组件需要适配引擎的命令式与事件回调交互接口 |

## 决定

选 **方案 C**，因为：
1. **关注点彻底分离**：音视频解码管线和时钟控制是严谨的时间状态机，将其与 React 的组件重渲染机制完全解耦，能彻底终结状态撕裂和 Ref 爆炸。
2. **连续阻尼平滑消除震荡**：原有的硬编码 $1.08 / 0.92$ 跳变容易在阈值边界来回抖动，改用连续阻尼比例调速公式：
   $$\text{rate} = \text{baseRate} \times \left(1 + \frac{\text{expectedT} - \text{currentTime}}{\tau_{\text{damping}}}\right)$$
   使速度随误差平滑指数收敛，既保证了毫秒级追赶精度，又完全消除了声调顿挫感。
3. **消除代码重复**：一举清空 `Workbench.tsx` 与 `ExportPage.tsx` 中数百行冗余代码，两处共享同一个健壮经过测试的核心时钟基座。

## 代价

- 我们接受：React 组件不再直接操控 `video.currentTime` 与 `video.play()`，而是通过引擎句柄进行交互，需要简单维护引擎实例生命周期。
- 我们放弃：在 React Hook 内部继续打补丁的妥协做法。
- 后面要还的债：无。该引擎为纯 TypeScript 类，输入参数与对外事件均具有明确的类型契约。

## 什么情况下需要重新讨论

- 如果未来移动端全面普及 WebCodecs 且支持双路 4K 硬件硬解而不受内存限制，评估是否将播放内核全面从 HTMLVideoElement 升级为 WebCodecs Frame 流渲染。
