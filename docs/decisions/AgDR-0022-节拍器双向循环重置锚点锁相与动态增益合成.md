# 节拍器双向循环重置锚点锁相与动态增益合成

> 在对比台与导出预览采用循环重放策略的处境下，面对循环后节拍器哑音、起播吞音导致重拍未卡死锚点、以及纯正弦波音量在 -5.9 LUFS 高响度伴奏下极微弱的顾虑，我决定在引擎与合成器两端建立循环自愈重置机制，以统一时间轴 $\tau = 0$ 为绝对同相基准重构重拍同余与起播容差判定，并采用复合谐波敲击音色接入动态压缩器管线，以达成循环重放不断音、重拍精确卡死锚点且声音清晰饱满的目标，并接受小幅增加 WebAudio 节点连接与微小计算开销的代价。

## 考虑过的方案

| 方案 | 好处 | 代价 |
| --- | --- | --- |
| 方案 A：纯外部组件在 `onTauUpdate` 比较时间差调 reset | 不改动底层类内部状态逻辑 | 状态容易脱离受控范围，外部若有任何一次漏调或寻道并发，节拍器即永久哑火 |
| 方案 B：双层闭环重置 + 绝对同相锚点锁相 + 谐波动态压缩合成 | 彻底杜绝重放与向后 seek 哑音，$\tau=0$ 锚点重拍严格同相且起播不漏拍，高响度伴奏下穿透力极强且零破音削顶 | 节拍器内部需维护微小容差状态机，实时与离线音频管线需接入压缩器或离散限幅 |
| 方案 C：使用外置音频 Click 采样切片播放 | 音色可任意定制 | 引入外部音频 asset 依赖，增加加载与打包体积，慢放重采样复杂度升高 |

## 决定

选 **方案 B（双层闭环重置 + 绝对同相锚点锁相 + 谐波动态压缩合成）**，因为：
1. **第一性原理根治循环哑音病灶**：节拍器哑音的根本原因是其内部 `lastBeatIndex` 依赖单调递增，视频从终点跳回起点时，新时间对应的拍号远小于历史终点拍号，导致判定条件 `currentBeatIndex > lastBeatIndex` 永久为假。采用双层闭环设计：同步引擎在触发回绕时规范化更新；同时在 `SynthesizedMetronome` 内部，当检测到 $currentBeatIndex < lastBeatIndex$ 时，自动按新时间戳与起播容差重算 $lastBeatIndex$，实现无论任何场景（循环、反向拖拽、跳转）均能瞬时自愈发声；
2. **以统一时间轴 $\tau = 0$ 绝对锁相锚点重拍**：全时间轴严格以 $\tau = 0$ 对应拍号 $k = 0$。小节重拍判定使用全域同余规范 $((k \bmod 4) + 4) \bmod 4 == 0$，消除 JavaScript 负数取模缺陷；引入起播容差窗口（$\epsilon = 35\text{ms}$），当在 $\tau = 0$（或任意拍点附近）起播时，立即触发该拍发声，彻底解决此前在锚点起播首拍被吞、用户误以为重拍错位的问题；
3. **复合谐波与动态范围压缩器消除听觉掩蔽**：参考实测《金刚_真龙.mp4》等 WOTA 艺代表性伴奏音频高达 -5.9 LUFS / -8.8 dB RMS 的极高响度与动态压缩特性，单纯正弦波必然被掩蔽。升级为富含打击敲击谐波的脉冲波形（强拍 1500Hz/800Hz 复合脉冲，弱拍 800Hz 纯净脉冲），脉冲保压与衰减延长至 55ms，在 WebAudio 链路中接入 `DynamicsCompressorNode`，提升主增益 1.5 倍，确保即使在手机或笔记本单薄扬声器外放时依然清晰穿透且不爆音。离线 MP4 导出音轨同步升级相同离散时间戳与能量包络。

## 代价

- 我们接受：WebAudio 上下文内部额外创建一个 `DynamicsCompressorNode`（开销微秒级，完全可忽略）。
- 我们放弃：单调递增且不具备自愈能力的旧节拍器时序模型，以及单薄无谐波的 35ms 纯正弦波。
- 后面要还的债：如果未来用户提出自定义拍号（例如 3/4 拍或 6/8 拍），需要将硬编码的 4 拍周期解耦为配置变量（目前 WOTA 艺曲目 100% 均为 4/4 拍）。

## 什么情况下需要重新讨论

- 如果未来 WOTA 艺出现大量 3/4 拍或非 4/4 拍的特殊曲目需要支持变拍子节拍器时，重开此记录。
