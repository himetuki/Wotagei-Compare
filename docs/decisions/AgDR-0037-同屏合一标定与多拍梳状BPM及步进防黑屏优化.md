# 同屏合一标定、全站AB蓝绿规范与多拍梳状BPM及步进防黑屏优化

> 在实机审阅 v1 方案后发现：(1)「空间|时间」子模式仍增加了切页心智，且现代手机屏幕足以同屏操作；(2)「参考轮廓」对熟知警报动作的练习者属多余遮挡；(3) 48kHz / 44.1kHz 下单拍自相关与粗网格引发 `[A]ddiction` 164→163 与《嘘の火花》188→190 的 BPM 漂移；(4) 长 GOP 视频初进对比台暂停态直接步进时，未预热解码与寻道期间清屏纯黑导致首帧等 2～3 秒才出图；(5) `A/B` 配色不统一且顶部下拉小箭头不易辨识，我决定：
> 1. 彻底移除 `AlertSilhouette` 参考轮廓（取代 `AgDR-0036`）；
> 2. 合并空间三线与底部可拖拽定位波形面板到同一视图同屏操作，保留顶栏 `空间● / 时间●` 仅作只读完成状态小点指示（部分取代 `AgDR-0034`）；
> 3. 重构 [src/core/audio.ts](../../src/core/audio.ts) 为 ~250Hz 起音包络 + 多拍周期谐波梳状（`1T/2T/4T/8T/16T`）高精度 BPM 检测；
> 4. 修复 [SafeVideoController.seek](../../src/core/sync-engine.ts) `readyState < 2` 短路问题，并在 [Workbench](../../src/components/Workbench.tsx) 引入“非播放态及寻道前抓拍锁存 + 离屏最近已就绪帧防黑屏缓存 + 播放期零拷贝直通”（同时修复 [ImportStep](../../src/components/ImportStep.tsx) 到 [CalibrationStep](../../src/components/CalibrationStep.tsx) 跨卸载异步音轨合入）；
> 5. 统一全站 `A` 为蓝色、`B` 为绿色，并将顶部折叠拉手收起态/展开态文字分别改成 **「更多」** / **「收起」**；
> 以达成一次看全一次标好、曲速稳准、步进跟手零黑屏、全界面语义统一的体验，并接受同屏垂直布局略微收紧视频高度及维护少量离屏帧缓存内存的代价。

## 考虑过的方案

| 方案 | 好处 | 代价 |
| --- | --- | --- |
| **方案 A（入选）：波形 Canvas 兼作全屏拖拽时间轴 + 46px 波形高度 + 顶栏只读点** | 省去 32px 独立 slider 行，在 384px~430px 手机横屏依然保留大画幅三线拖拽区；一边划波形找起手拍一边调三线与「设为锚点」一步到位；状态点一眼确认而不误导点击 | 需要将波形 `<canvas>` 升级为全指针捕获搓帧交互 |
| **方案 B：在多拍梳状之外保留固定 `hopSize=512` 仅回退 `92a5bd8`** | 仅修复 48kHz 上单个视频 | 无法解决 44.1kHz `[A]ddiction`（`hop=512` 下 164→163）的半格量化问题，也不兼容 16kHz 原生流 |
| **方案 C：保留 `subMode` 切换并只加快播放速度优化** | 不改单视频页面 | 用户实机痛点明确指出「应该放到一起」「不要点击切换」 |

## 决定

选 **方案 A + 多拍梳状 BPM + 离屏末帧缓存零黑屏**，因为：
1. **以实机真实痛点为准**：WOTA 艺找起手帧与对拍本就发生在同一张起手画面周围，去掉轮廓叠层与子模式切换后，顶栏更简洁、同屏即可联动完成空间与时间两个维度；
2. **多拍小节对齐解决根本物理偏差**：单拍自相关（`1T`）会因切分音和 ~11.6ms 粗糙包络而落偏 ±1~2 BPM，把 `4ms` 高分辨率包络与 `2T/4T/8T/16T` 乐句级谐波结合起来，能在毫秒级算力开销内精确锁死在 `164` / `188` 等真实曲速；
3. **零黑屏缓存消灭感官卡顿（且避免倒退寻道）**：长 GOP MP4 的首次随机寻道必然耗时大于普通帧间隔（若强行微播再倒退 `seek` 反而触发二次全 GOP 重解码）。通过修复冷节点 `0s` 强制寻道、在非播放态与寻道前锁存已就绪帧、以及全速播放期零拷贝直通，既实现任意步进过程画面连贯零闪黑，又不损伤播放与冷启性能。

## 代价

- 我们接受：放弃「参考轮廓」开关（`AgDR-0036` 状态置 `superseded`）和单视频页内手动切换 `空间|时间` 模式；
- 我们接受：对比工作台维护两张轻量级离屏 `<canvas>` 缓存最近一帧解码图像；
- 后面要还的债：实现验收后同步将本记录状态改为 `executed`。
