# 系统状态栏与虚拟金刚键安全区避让布局

> 在 Android 手机与平板横屏运行且用户启用常驻系统状态栏或经典三键导航（金刚键）的处境下，面对边缘操作按钮与状态信息被系统栏遮挡、点击时频发误触系统返回/桌面键的顾虑，我决定采用「纯黑底色铺满 + 交互内容安全区动态避让」的双层布局架构，以达成全机型、全导航模式下界面无遮挡、零误触的交互可用性目标，并接受需在全局 CSS 及各核心容器精细化管理安全边距的代价。

## 考虑过的方案

| 方案 | 好处 | 代价 |
| --- | --- | --- |
| 方案 1：强制原生沉浸全屏隐藏系统栏（Immersive Sticky） | 页面拥有全屏物理像素，无需改动现有边距 | 剥夺用户查看时间/电池和习惯按键的权利；边缘滑动呼出系统栏时依然发生遮挡，且与底部手势严重冲突；部分机型沉浸式表现不可靠 |
| 方案 2：外层容器硬编码固定边距（如固定 padding 48px） | 实现简单直接 | 在手势导航手机或 PC 浏览器端产生大面积黑边浪费；无法适应不同机型金刚键尺寸的差异（从 40px 到 72px 不等） |
| 方案 3：CSS `env(safe-area-inset-*)` 驱动的双层避让架构（底色铺满 + 内容安全内嵌） | W3C 标准；有系统栏时自适应避让，无系统栏或手势模式时自适应为 0 零浪费；底色无黑边违和感；从根源解决误触与遮挡 | 需要在全局 CSS 变量层统一定义安全边距并在顶栏、底栏、工具条、画布舞台及弹窗层统一应用与测试 |

## 决定

选 **方案 3：CSS `env(safe-area-inset-*)` 驱动的双层避让架构**，因为：
1. **符合第一性原理与用户交互自主权**：用户选择使用金刚键或常驻状态栏是其个人操作习惯，应用层应当主动适应宿主系统，而不是强行隐藏或假定不存在。
2. **动态自适应与零多余空白**：当系统存在金刚键（横屏常在右侧或左侧）或状态栏时，WebView 自动将对应尺寸注入 `env(safe-area-inset-*)`，界面仅在必要侧让出空间；在手势导航或桌面端，边距自动回落为基础间距（如 12px），实现像素级紧凑与舒适。
3. **视觉与交互关注点解耦**：背景层保持 100vw × 100vh 延伸，维持沉浸纯黑底色；而交互层（按钮、徽章、滑块、时间轴、弹窗）严格收拢在安全框内部，彻底消除误触金刚键导致退出应用的严重体验事故。

## 代价

- 我们接受：顶部导航栏与底部操作栏的实际高度与内边距会随设备安全区动态增加，需确保高度和居中计算采用 `calc()` 与 `max()` 表达式。
- 我们接受：画布标定手柄与对比画幅的容器尺寸计算需基于安全视口（Safe Viewport），避免边缘触控手柄落入金刚键边缘。
- 我们放弃：写死绝对像素贴边（`left: 0`, `right: 0`, `top: 0`, `bottom: 0`）并假定用户一定处于全屏无栏环境的简化思维。
- 后面要还的债：在后续新增全屏弹层或悬浮控件时，必须遵循继承自全局 `--safe-*` 变量的避让规范。

## 什么情况下需要重新讨论

- 如果 Android 平台推出全新的窗口多任务或窗口内缩规范，导致 `env(safe-area-inset-*)` 无法准确反映金刚键宽度时，需重新讨论是否引入原生插件向 Web 注入尺寸。
