# 移动端横向视口紧凑重构与状态冗余全面清除

> 在 Android 手机横屏运行且可用逻辑视口受金刚键挤压缩窄至 650px~800px 的处境下，面对单行控件超宽导致最右侧操作按钮与状态区被截断挤出屏幕、且界面多处存在重复 BPM 徽章冗余的顾虑，我决定彻底剔除重复状态、精简导航文字、收敛平铺展开型控件并建立自动化移动端仿真检验底座，以达成全向导链路在任意狭窄横屏视口下零溢出、零截断、极简干净的交互体验目标，并接受需简化部分非关键次要平铺按钮的代价。

## 考虑过的方案

| 方案 | 好处 | 代价 |
| --- | --- | --- |
| 方案 1：保留所有平铺控件，允许底栏水平滚动（Scrollable Overflow） | 不删减现有任何按钮 | 在移动端小屏幕横屏下水平横滚操作极易与时间轴/波形滑动冲突；用户看不到右侧隐藏按钮，以为功能丢失；完全违背专业监视器全景掌控原则 |
| 方案 2：分多行堆叠排布（Multi-line Wrap） | 所有元素垂直增加行数容纳 | 横屏垂直高度仅 360px~390px，再增加底栏行数会严重压缩中间核心视频画布，导致画面被挤扁成一条细缝 |
| 方案 3：全面清除冗余状态 + 控件紧凑收敛 + 弹性自适应宽度保护 | 彻底根除撑爆问题；界面专业极简；关键操作百分之百完整展现；视频监视区域最大化 | 需要删除顶栏常驻 BPM 重复徽章，对拍页移除平铺慢放组，步骤导航字数精简 |

## 决定

选 **方案 3：全面清除冗余状态 + 控件紧凑收敛 + 弹性自适应宽度保护**，因为：
1. **符合第一性原理**：横屏交互的本质是“高精度的画布可视化”与“直达式触控”。界面中一个状态只应存在一个真实源，顶栏已有了步骤，底栏已有 BPM 可调输入，顶栏再挂两个只读的 BPM 标签毫无意义，纯粹是在浪费宝贵的横向像素。
2. **根治横向撑爆（Horizontal Overflow）**：通过将 6 步导航条精简为紧凑字样（01导入、02空间1...）、移除对拍页不必要的慢放组、收敛工作台展开项，整行固定宽度直接从 860px 骤降至 580px 以内，即便在 650px 的超窄小屏下，最右侧的「下一步」与「BPM 调整/导出」依然拥有充足的余量，绝对不会被截断。
3. **闭环仿真保障**：集成基于 Playwright 的自动化移动端视口仿真与截图，确保每一步修改都有实机视口检验证据，杜绝主观臆测。

## 代价

- 我们接受：删除顶栏常驻的 `CH1/CH2 BPM` 徽章，仅在对拍步骤与对比工作台中按需呈现与微调。
- 我们接受：将全局步骤条由「02 视频1空间」精简为「02 空间1」，「04 视频1对拍」精简为「04 对拍1」。
- 我们接受：在音频对拍步骤中移除 0.25x/0.5x/1.0x 慢放预览组（慢放对齐属对比工作台核心职责，对拍步骤以逐帧与波形为主）。
- 后面要还的债：如果未来新增更多的复杂对比参数，必须遵循单点入口原则，不得随意在全局顶栏平铺展开。

## 什么情况下需要重新讨论

- 如果用户明确提出需要在所有步骤随时纵览双通道 BPM 且提出了不侵占主横向宽度的浮层或折叠交互形式，可重新评估。
