# 全局网格对齐与自相关抛物线插值BPM检测

> 在用户微调音频时间标定截取端点时，面对离散网格粗糙、鼓点瞬态相位撕裂与先验权重偏置导致 BPM 在 181/188/194 剧烈跳变的处境，我决定在切片时将采样点对齐至全局 Hop 整数倍网格，并在物理自相关局部峰值上执行亚样本二次抛物线极值插值，以实现截取端点微移时 BPM 稳定锁定且误差收敛在 0.2 BPM 以内，并接受极小片段边界处至多丢弃不足 1 个 hop 样本的微小代价。

## 考虑过的方案

| 方案 | 好处 | 代价 |
| --- | --- | --- |
| 方案 A：提高包络采样率（如 hopSize 从 512 降至 64） | 分辨率提高，整数网格变细 | 自相关计算量激增 64 倍（$O(N^2)$），在移动端拖拽切片时严重掉帧甚至卡顿 |
| 方案 B：切片网格对齐 + 物理自相关抛物线插值 | 计算量完全零增加（仅 3 点抛物线极值公式与采样点 floor 对齐），彻底消除相位撕裂与网格阶跃 | 截取区间起止点会向外或向内吸附至最近的 10.6ms 网格边界（人耳完全不可感知） |
| 方案 C：全音频预计算起音包络，切片直接切索引 | 计算最快，全局绝对相位一致 | 内存需长期驻留整首曲目的 Float32 起音包络数组，且需要调整全局数据流状态架构 |

## 决定

选 **方案 B（切片网格对齐 + 物理自相关抛物线插值）**，因为：
1. **第一性原理精准打击病灶**：跳变的主因是鼓点瞬态在 512 样本块边界上的能量泄漏与粗糙整数离散化。将切片起始采样点按 `hopSize` 整数倍下取整（`Math.floor(validStart * sampleRate / hopSize) * hopSize`），保证所有鼓点相对于局部块边界的相位恒定；
2. **极简数学解析解**：三点二次多项式拟合极值公式 $\Delta = \frac{y_{k+1} - y_{k-1}}{2(2y_k - y_{k-1} - y_{k+1})}$ 具有极高解析精度，直接在未受先验倾斜污染的原始相关系数 $y$ 上提取真实物理极值，瞬间消除 6~7 BPM 的粗暴台阶，算力开销仅几次浮点四则运算；
3. **零架构浸润**：无需侵入 AppState 或扩展全局结构，纯函数层 `src/core/audio.ts` 内部闭环解决。

## 代价

- 我们接受：切片时有效采样点范围会有至多不足 512 个样本点（在 48kHz 下约为 10.6ms）的网格边界吸附。
- 我们放弃：直接拿整数 lag 换算 BPM 的简单写法。
- 后面要还的债：如果未来遇到极端 BPM 渐变曲目（如转速渐快/渐慢），需要扩展为分段速度场映射。
