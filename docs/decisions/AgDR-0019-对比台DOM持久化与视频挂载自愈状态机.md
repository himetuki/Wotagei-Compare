# 对比台 DOM 持久化与视频挂载自愈状态机

> 在对比播放工作台与独立导出片段页之间频繁切换的交互场景下，面对 `<video>` 元素反复销毁重挂导致同步引擎脱节、Canvas 渲染崩溃以及视频黑屏不可见的问题，我决定采用对比台视口 DOM 持久常驻（导出时仅做 `display: none` 隐藏与播放暂停）结合双通道视频挂载动态自愈（Dynamic Ref Re-attachment）与元数据加载拦截寻道状态机，以达成无缝瞬时画面复现、零幽灵时钟与 100% 渲染高可靠性，并接受导出期间在 DOM 中多保留两个暂停态隐藏 `<video>` 标签的微小内存代价。

## 考虑过的方案

| 方案 | 好处 | 代价 |
| --- | --- | --- |
| **方案 A（入选）：对比台 DOM 持久常驻 + 导出层并存显隐 + 动态挂载自愈与元数据拦截** | 对比台 `<video>` 与 `<canvas>` 从不被销毁，切换回对比台零延迟即时呈现当前帧；引擎即使遇到 DOM 重建也能自动自愈重绑并同步初相位 | 导出页打开期间 DOM 中存在对比台隐藏的 2 个 `<video>` 标签（处于暂停态无解码消耗） |
| **方案 B：将对比台与导出页彻底拆解为 App 顶层独立互斥步骤，每次切回全量从零初始化** | 各步骤生命周期彻底解耦 | 切换步骤时视频需要重新加载元数据与硬寻道，产生 200ms~500ms 的明显白屏/黑屏闪烁，且难以保留工作台微调后的视口缩放与慢放临时参数 |
| **方案 C：保持现有早期条件返回卸载 DOM，仅在切回时利用 Effect 强行刷新 DualVideoSyncEngine** | 表面代码改动最少 | 每次切回必须等待视频重新 `loadedmetadata` 并触发硬 seek，移动端 WebView 频繁销毁创建解码管线极易造成硬件解码器泄露或偶发黑帧卡死 |

## 决定

选 **方案 A**，因为：
1. **第一性原理与零延迟感知**：对比台是用户高频使用的核心扒技工作台，导出片段是下游临时操作。既然用户从导出页返回对比台期望立刻回到离开时的精准帧画面，保持对比台底层 DOM 存活是最直接、最自然的单页面架构解法。切换时将对比台容器设为 `display: none` 并调用 `engine.pause()`，浏览器会立刻停止视频画面的高频解码与渲染开销，移动端硬件压力几乎为零。
2. **生命周期自愈（Defensive Re-attachment）**：即使用户通过外部步骤（如修改时间标定或空间标定）导致 `Workbench` 整体重新挂载，或者在某些边缘异常下 video 节点发生变更，通过视频引用的响应式绑定，一旦检测到 video 节点实例变更或新进入视口，立即调用 `engine.attachVideos(v1, v2)` 并执行一次基准初相寻道（`seekToTau(tau)`），确保引擎绝不与脱水 DOM 绑定。
3. **消除元数据未加载寻道截断 Bug**：现存 `SafeVideoController.seek` 在 `readyState < 1`（元数据未加载、`duration` 为 `NaN`）时误将目标时间截断为 0 并静默丢弃。增加对元数据加载状态的拦截与事件监听，确保寻道目标在元数据就绪后精准生效。
4. **渲染循环异常熔断守护**：在 Canvas 2D 纯渲染循环中对 `ctx.drawImage` 增加 `readyState >= 2` 守卫与 `try...catch` 保护，防止个别浏览器因视频解码瞬间状态异常（如 InvalidStateError）彻底搞崩 `requestAnimationFrame` 驱动循环。

## 代价

- 我们接受：在进入导出片段视图时，对比台主视图节点依然驻留于 DOM（`display: none`），需要显式停止对比台的播放与节拍器；
- 我们放弃：早期通过条件分支 `if (isExport) return <ExportPage />` 直接替换整个渲染树的写法；
- 后面要还的债：无。

## 什么情况下需要重新讨论

- 如果在某些极度受限的超低端 Android 设备上，WebView 严厉限制后台暂停态 `<video>` 标签数量导致解码管线冲突，需评估在隐藏时动态释放 `src` 或将导出参数状态完全提升至全局 Store。
