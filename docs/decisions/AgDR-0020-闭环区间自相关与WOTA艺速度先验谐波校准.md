# 闭环区间自相关与WOTA艺速度先验谐波校准

> 在多歌曲技连视频时间标定中，面对 45s 硬截断导致停止点假死以及日系流行乐 3+3+2 附点切分音将 165 BPM 误判为 110 亚谐波的问题，我决定彻底废除固定长度截断并将计算范围严格闭环于 $[trimStart, trimEnd]$ 内部，引入以 168 BPM 为中心的对数正态先验加权与 3:2 / 1:2 谐波共振校验，并在手柄松开时执行防抖测算，以达成精准、稳定且抗切分音干扰的局部 BPM 识别，并接受极短区间（<2s）无法独立提供有效周期的代价。

## 考虑过的方案

| 方案 | 好处 | 代价 |
| --- | --- | --- |
| 方案 A：保持原样，仅在 UI 上增加提示引导用户手动输入 BPM | 零算法改动风险 | 自动化体验极差，停止手柄假死与 110/165 串扰严重影响小白用户 |
| 方案 B：引入重度第三方 MIR WebAssembly 库（如 Essentia.js） | 算法全面，具备完整 onset 分离 | 依赖包体积暴增数 MB，冷启动与 Android 移动端执行开销过大 |
| 方案 C（本方案）：闭环样本切片 + 168 中心对数正态先验 + 1.5x/2x 谐波复核 + 释放防抖 | 零新增第三方依赖，计算量在毫秒级，数学原理清晰且完全适配 WOTA 艺场景 | 极慢或非 WOTA 艺曲目（如 <90 BPM 的慢抒情歌）若与 1.5 倍频重叠会受先验轻微抑制，需依靠 Tap 补充 |

## 决定

选 **方案 C**。
1. 真实截取区间 $[trimStart, trimEnd]$ 是唯一的真理范围，彻底删除 `maxScanLength` 机械截断前 45 秒的代码，使停止点拖动即刻生效。
2. WOTA 艺曲目黄金速度集中在 150 ~ 190 BPM，通过以 168 BPM 为中心的高斯/对数正态权重 $W(bpm) = \exp\left(-\frac{(\log_2(bpm) - \log_2(168))^2}{2\sigma^2}\right)$ 自然压制 80 ~ 120 慢速切分音。
3. 针对日系歌曲常见的 110/165（3:2）切分音尖峰，增加 1.5 倍频谐波探测，只要 1.5 倍频存在共振，无条件采信真实高速节拍。
4. 手柄拖动过程中仅平滑刷新时间戳与视觉，在释放（`PointerUp`）或停止后防抖触发重算，避免半成品选区污染。

## 代价

- 我们接受：当用户选取的招式区间极短（小于 2 秒，不足 1 个小节）时，因样本过短无法进行有效周期估计，算法保持前序 BPM 不变。
- 我们放弃：纯通用型音频软件对极慢速音乐（如 70 BPM 蓝调爵士）的优先推断权，全面优先服务 WOTA 艺 140~200 BPM 的高速击打场景。
- 后面要还的债：如果未来扩展到非 WOTA 艺的一般舞蹈领域，可将 168 先验中心作为可配置参数暴露。

## 什么情况下需要重新讨论

- 如果用户大量输入包含 6/8 拍复合节拍（而非 4/4 拍切分音）且真实 BPM 确定为 110 的特殊慢速舞曲时，需重开此条讨论以引入显式拍号配置。
