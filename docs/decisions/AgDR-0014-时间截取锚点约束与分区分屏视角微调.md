# 时间截取锚点约束与分区分屏视角微调

> 在时间标定中用户频繁截取技连招式、原有允许锚点落在截取区间外的策略导致时间轴逻辑混淆，且对比台分区分屏在大幅度挥棒时存在两侧中缝与高空切边顾虑的处境下，面对原锚点失准、盲区播放以及手长舞者光弧被截断的问题，我决定：
> 1. 推翻 AgDR-0013 中“锚点不强行 Clamp”的旧决策，规定锚点时间戳必须严格位于截取区间 $[trimStart, trimEnd]$ 内部，区间缩窄出界时自动 Clamp 到最近端点，手动输入或设为锚点时亦强制 Clamp；
> 2. 时间标定播放控制改为在 $[trimStart, trimEnd]$ 截取区间内循环播放，拖动手柄时自动暂停视频并实时驱动视频帧与播放游标贴合正在拖动的端点；
> 3. 对比台左右分区分屏的人体理论垂直中轴线各自向屏幕外侧微调（左半区中轴设为 47.5%，右半区中轴设为 52.5%），并将人体特征高度在半区中的占比由 69% 略微收敛至 65%~66%，脚底保持 95% 沉底，头顶留白由 26% 增至约 29%~30%；
> 以达成标定状态零歧义、即时手柄寻帧、分屏同台时高空与侧向大光弧辽阔完整展示的目标，并接受截取区间缩窄时原锚点时间戳会被自动修改为边界时间的代价。

## 考虑过的方案

| 方案 | 好处 | 代价 |
| --- | --- | --- |
| **方案 A：保持锚点不变，仅在进入对比台时警告或报错** | 保持用户之前手动对好的锚点数值不动 | 截取区间外存在锚点违背了截取的核心意义（聚焦该招式），对比台时间轴交集换算产生虚假偏移甚至负时间盲区；用户需要手动找回锚点，体验断裂 |
| **方案 B（入选）：锚点强制 Clamp 至 $[trimStart, trimEnd]$，手柄拖动实时寻帧停播，分屏中轴微幅外偏 + 比例微降至 65%** | 锚点永远合法，时间轴交集换算无死角；拖动手柄即刻看到起止动作帧；左右分屏给内侧大挥棒腾出更多空间，高空留白提升至近 30%，彻底消除手长光弧切顶风险 | 截取区间剧烈变动时原锚点可能被端点覆盖，需要用户在截取稳定后重新核准起拍锚点（但在 WOTA 艺技连中，先定招式起止范围再定起拍原点本就是最自然的流水线） |
| **方案 C：分屏保持 50% 居中，大幅缩小人物比例至 50%~55%** | 无论怎么挥棒都绝不出界 | 彻底丧失移动端小屏极清、观察肌肉发力与手腕细节的优势，违背 AgDR-0013 的大比例初衷 |

## 决定

选 **方案 B**，因为：
1. **第一性原理与单一真实源**：既然定义了 $[trimStart, trimEnd]$ 为招式的唯一有效时间边界，那么该招式内的起拍锚点就必然属于该闭区间。允许锚点孤立在区间外不仅会导致统一时间轴换算出现边界溢出，还会使用户产生“锚点为什么对不上截取画面”的认知混乱。强制 Clamp 是最干净、最简单的逻辑；
2. **即时交互反馈闭环**：拖拽起止手柄时，用户最需要看清的是“这个招式动作到底是在哪一帧开始和结束的”。在拖动手柄时自动暂停视频，并让底层监看画面实时 seek 到正在拖动的时间点，能省去用户来回拖动底部进度条寻帧的繁琐步骤；
3. **播放区间语义收敛**：时间标定是针对特定招式的标定，用户点击播放理应只检查当前截取的目标片段，播放至右边界自动循环回到左边界，与对比台的闭环播放保持一致；
4. **分屏微调克制实用**：用户明确强调“一点点就可以！真的不能太多了！”。左半区中轴由 50% 微移至 47.5%（仅偏移 2.5% 半区宽度），右半区由 50% 微移至 52.5%，既保留了人体在左右半区的视觉稳定感，又给两臂内侧大挥棒拉出了 5% 宽度的宝贵安全通道；同时特征高度比例由 69% 调整至 65%~66%，头顶留白自然扩张至约 30%，手长大动作光弧不再切顶。

## 代价

- 我们接受：当用户大幅收窄截取区间导致原锚点被截断时，锚点时间戳会被直接 Clamp 并覆盖为截取端点数值（放弃 AgDR-0013 遗留的不 Clamp 代价）；
- 我们接受：左右半区在分屏模式下不再是绝对几何几何中心（50%），而是各自带有 2.5% 的外偏，但该微小偏移在视觉上几乎不可察觉，却显著改善了挥棒边界表现；
- 我们放弃：时间标定中播放器通篇无边界播放的旧行为，统一收敛为截取区间内的闭环循环。

## 什么情况下需要重新讨论

- 如果用户要求在对比台中支持单通道独立调整视口平移缩放或支持多招式列表切换，重开此记录。
