# 锚点试听视频时钟一次性重拍与自由秒数编辑契约

> 在【单视频标定页点击「试听」使用固定 `setTimeout` 触发弱音正弦提示且与普通播放、视频缓冲缺少精准同步，同时锚点手动输入框在 `onChange` 阶段立刻调用 `commitAudioState` 强制重写 `toFixed(3)` 导致编辑极其痛苦】的处境下，面对【如何保证“仅试听触发一次与视频帧严格同步的重拍”、普通播放及循环不误响，以及如何在不破坏底层 `number` 校验的前提下让锚点输入流畅自然】的顾虑，我决定【在 `CalibrationStep` 中用受视频时钟驱动的一次性 `auditionPendingRef` 状态 + `SynthesizedMetronome.playClick(true)` 替代 `setTimeout` 定时器，并将 `anchorInputText` 从 `commitAudioState` 的副作用中解耦，仅在 `onBlur` / `Enter` 时统一钳位并执行 `toFixed(3)`】，以达成【试听声画严丝合缝且与普通播放彻底隔离、手动输入毫秒秒数丝滑不跳字】的目标，并接受【`CalibrationStep` 持有一份轻量 `SynthesizedMetronome` 实例与试听武装标志】的代价。

## 考虑过的方案

| 方案 | 好处 | 代价 |
| --- | --- | --- |
| **方案 A（入选）：视频时钟跨锚点一次性武装标志 + `SynthesizedMetronome.playClick(true)` + 输入字符串态解耦** | 完全消除固定 `setTimeout` 在移动端寻道/缓冲导致的提前误鸣；复用节拍器高穿透重拍音色与压缩器；仅在点击「试听」时武装并在跨越瞬间消费，普通播放、暂停重放、循环二周目绝不误触发；输入态与对比台自定义步进完全一致 | 需要在 `updateLoop` 中维护前一帧时间与 `seeking` 守卫以防寻道尚未完成时的旧时间戳误触 |
| **方案 B：继续使用 `setTimeout` 仅把发声换成重拍音色** | 改动极小 | 移动端视频 `currentTime = preRoll` 后往往需要 100~300ms 寻道解码起播，`setTimeout` 依然会在视频还没到达锚点帧时提前发声；若用户中途拖动波形或暂停，定时器清理不严仍易错鸣 |
| **方案 C：修改锚点输入框为纯截断不补零字符串解析** | 可省略 `toFixed(3)` | 违背“采用自定义步进粒度这样的秒数输入方式，失焦 `toFixed(3)` 格式化补全/规整”的明确交互约定 |

## 决定

选 **方案 A**，因为：
1. **时间真源与声学响度一致性**：视频画面的真实时刻由 `video.currentTime` 决定而非 JS 挂钟 `setTimeout`。对比台使用 `SynthesizedMetronome.playClick(true)` 时底层视频均处于静音态，而标定页需要边听原曲边核对拍点，原曲满幅输出会导致混音动态余量被系统限幅器压缩。因此点击「试听」时先在用户点击手势内预热 `SynthesizedMetronome` 音频上下文，同时在试听窗口内将原片 `<video>` 伴奏压低至 `0.3`（预留 ~10.5 dB 瞬态余量），跳转至 `preRoll = Math.max(0, anchorTime - 0.6)` 并武装 `auditionPendingRef`；在 60fps `requestAnimationFrame` 循环中校验 `!video.paused && !video.seeking && video.readyState >= 2`，当 `video.currentTime >= anchorTime` 时立即调用 `playClick(true)`（与对比台重拍完全相同的 1600Hz+800Hz 压缩脉冲响度）并解除武装，停留 200ms 后用 180ms 平滑淡回 `1.0`；
2. **严格的普通播放与音量恢复隔离**：点击普通「播放」按钮（`togglePlay`）、暂停、拖动波形、拖动裁剪手柄或区间循环回绕时，一律显式清空 `auditionPendingRef` 武装状态并立即恢复 `video.volume = 1.0`；
3. **输入框读写分离**：`commitAudioState` 仅更新 `anchorTime` 与上层 `audioInfo`，不再反向改写正在聚焦编辑的 `anchorInputText`；仅当非编辑场景（切换视频、拖动波形/手柄缩窄越界钳位、点击「设为锚点」、输入框 `onBlur` 或按下 `Enter`）才将 `anchorTime.toFixed(3)` 写入 `anchorInputText`。

## 代价

- 我们接受：`CalibrationStep` 需持有一个 `SynthesizedMetronome` 实例（组件卸载时 `dispose()`）及 `auditionPendingRef` 状态；
- 我们放弃：基于 `setTimeout` 估算延迟的开环试听机制；
- 后面要还的债：无额外技术债务。

## 什么情况下需要重新讨论

- 如果未来需要在单视频标定页也增加“全程开启连续节拍器跟拍播放”开关，可将一次性 `auditionPendingRef` 扩展为跟拍模式切换，但默认行为仍须保持“普通播放不在锚点单独响重拍”。
